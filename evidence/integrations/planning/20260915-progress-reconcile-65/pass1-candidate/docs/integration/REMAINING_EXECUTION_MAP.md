## 넓은 출시 범위와 지금 구현 가능한 backend

44개 행은 모두 진행 대상이지만 동시에 닫을 수 있는 단일 backlog가 아니다. R/S0의 source·license truth, S1/S4의 실제 provider termination과 qualification, S5의 비교 cohort, A01/A03/A08의 release proof는 외부 사실 또는 실제 환경을 요구한다. fixture가 통과해도 이 행들은 열린 상태다.

현재 환경에서 의미 있게 전진할 수 있는 부분은 배포 host 설정과 탐색 요청의 durable 연결(S2-01~05), writer lease와 duplicate/final overwrite 방지(S3-01/S3-03), task-kind evidence와 recovery decisions(S4-02~05), 평가 dimension/accounting/promotion logic(S5-02~04/S5-07), 그리고 adversarial release fixtures(A02/A04~A07)다. 이 구현은 나중의 live gate가 무엇을 측정할지 고정하고 silent side effect를 줄인다.

## 우선 배정 가능한 독립 구현 단위

1. **S2 배포 설정·탐색 요청 연결.** 소유 파일: `daemon/src/selection/local-host-settings.ts`, `daemon/src/selection/initial-default.ts`, `daemon/src/selection/exploration-budget.ts`, `app/orchestration-driver.mjs`, 각 대응 `.d.mts`, 새/기존 focused tests `daemon/test/integration-initial-selection-baseline.test.ts`, `integration-exploration-budget.test.ts`, `integration-exploration-engine.test.ts`. 2. **S3 writer lease·restart duplicate gate.** 소유 파일: `daemon/src/workspace-lease.ts`, `daemon/src/orchestration/engine.ts`, `daemon/src/orchestration/store.ts`, `daemon/test/integration-orchestration.test.ts`, 필요한 새 focused lease test 한 파일. 3. **S4 task-kind evidence·failure decision matrix.** 소유 파일: `daemon/src/verification/requirements.ts`, `daemon/src/verification/evidence-policy.ts`, `daemon/src/orchestration/failure-diagnostic.ts`, `daemon/src/orchestration/recovery-policy.ts`, `daemon/test/integration-evidence-policy.test.ts`, `daemon/test/integration-verification.test.ts`, 새 decision-matrix test 한 파일. 4. **S5 evaluation completeness·promotion guard.** 소유 파일: `daemon/src/evaluation/observations.ts`, `measured-facts.ts`, `authoritative-accounting.ts`, `baseline-contract.ts`, `comparison.ts`, `daemon/test/integration-evaluation.test.ts` 및 matching focused evaluation tests.
