# R04/R05 selected-scope gap audit

## Verdict

R04 and R05 should remain open, but both have a bounded offline completion path for the same canonical selected scope used by R01, R02, R03, and R06. The blocker is not an unselected transport or a missing provider run. It is the absence of a fail-closed incorporation/test-separation contract over the selected fixture/tool components.

This audit does not treat the selected scope as empty. R-04, R-05, and R-06 select Cue-authored internal fixture/tool components; R-08 selects limited principles with zero external bytes. Deferred transports and unselected packages remain outside this scope.

## Original conditions

- **R04:** incorporate adopted components with pinned version/source notice, a thin adapter, and a required patch list.
- **R05:** pass Cue contract/regression and any necessary real-boundary verification separately from upstream tests.

Neither condition requires provider qualification when the selected seam is a pure local function. Conversely, a prose statement that no external package was adopted is insufficient because the selected Cue-native components are real internal reuse selections.

## Genuine gaps

### R04 gap: no enforceable incorporation matrix

The catalog and R-04/R-06 manifests contain most required facts, but no current validator requires them uniformly across the canonical selected set. `readSelectedReuseBasis` verifies selected bytes and descriptor paths; it does not enforce an R04 record containing, for every selected component:

- exact selected revision and current source bytes;
- source/notice disposition;
- exact Cue adapter/caller entry point;
- explicit patch ledger, including `[]` / `none`; and
- selection-specific applicability, so R-08 is principles-only N/A rather than adopted code.

R-05 is represented by a Markdown decision plus catalog row rather than the same validated manifest schema as R-04/R-06. Regenerating receipts after removing or weakening `sourceNotice`, `publicApiAndSeam`, or `patches` would change the digest but is not independently rejected as an invalid incorporation contract.

### R05 gap: no separate three-authority test matrix

Current evidence contains the necessary ingredients but not one validated record that separates them for the same selected revision:

1. **upstream test:** explicit N/A with a reason for Cue-authored selected bytes and zero incorporated upstream runtime/package bytes;
2. **Cue contract/regression:** pinned direct test command/result and current test/source hashes; and
3. **necessary real boundary:** pinned actual receipt-generator/verifier invocation that imports the selected function and verifies deterministic checked-in output.

The receipt currently stores historical execution metadata and current generated byte equality, but it does not label these three authorities separately or reject an unjustified upstream N/A, missing Cue regression, or absent necessary boundary. R-08 likewise needs an explicit no-executable-seam N/A rather than a fabricated boundary run.

No provider/live boundary should be imported for these pure fixture/tool seams. If a transport or product adapter is later selected, its R05 row will require the real boundary appropriate to that new seam; that future condition does not block the current selected-scope implementation.

## Bounded offline implementation plan

1. Add a canonical selected-incorporation record generated from `readSelectedReuseBasis`, with exactly R-04/R-05/R-06/R-08.
2. For R-04/R-05/R-06 require revision, current source refs, source notice, exact internal caller/adapter entry point, explicit patch list, and `adoptionAuthorized:false` limited fixture/tool scope. For R-08 require principles-only disposition, pinned commit, zero external selected bytes, current consumer refs, and incorporation N/A reason.
3. Add a separate selected-test record. For R-04/R-05/R-06 require:
   - upstream `not-applicable` only with the exact Cue-authored/zero-upstream-byte rationale;
   - current Cue test source and a pinned passing result; and
   - current receipt CLI consumer result as the necessary actual local boundary.
   For R-08 require all executable test/boundary cells to be N/A with the no-callable-seam reason and retain the hash-bound principles selection check.
4. Bind both record digests into `receipt.json` and make `--verify` regenerate and compare them byte-for-byte.
5. Add negative cases for missing/extra selected row, stale source or test hash, missing notice, missing/implicit patch list, caller outside the declared seam, unjustified upstream N/A, merged upstream/Cue/boundary authority, missing boundary, and any R-08 external-byte/adoption claim.
6. Run the focused receipt tests and exact current-path `--verify`; preserve the independent review before changing R04/R05 status.

## Closure boundary

Passing that plan would support R04 and R05 only for the current canonical fixture/tool and limited-principles selection. It would not authorize external component adoption, close deferred transport work, qualify a provider, prove actual billing semantics, or satisfy S1 lifecycle/product integration requirements.

This was a read-only audit except for this report. No source, test, build, provider, model, local-model, or network call was made.
