# Read-only verifier boundary done contract

Done means a distinct production boundary runs only a host-pinned verifier command in a capability-zero Windows AppContainer with recursive read/execute access to one approved worktree and modify access only to a separate owned runtime root. The same non-reparse worktree identity is checked before ACL grant, immediately before process resume, and after exit. The original security descriptor is restored exactly; process closure, profile removal, owned-root removal, durable verifier identity, and durable cleanup observation are all independently represented. Command exit success alone grants no acceptance, P13, model, provider, billing, Core, or Codex authority.

Source scope is new `daemon/src/readonly-verifier-*`, new `daemon/src/readonly-verifier-launch.ps1`, migration `039_readonly_verifier_identity.sql`, and focused tests/evidence. Existing writer launcher, process-launch, Core, orchestration host, and acceptance code remain unchanged. Migration 039 is valid only while 038 is the highest source migration; build must package an identical dist copy.

At most two implementation correction hypotheses are allowed. Every pass runs the focused pure/fixture tests, TypeScript no-emit, and scoped diff check. The coordinated final pass also runs the daemon build and source/dist migration and launcher hash comparison. A single real Windows probe may run only after an independent reviewer approves its frozen source, exact owned temporary paths, executable/script hashes, and one-attempt marker. It invokes no Codex, Claude, model, provider, Electron, user credential, repository command, process-kill experiment, or cleanup recovery gate.

Required hostile checks are wrong role/run/task/candidate/subject, mutable or malformed input, command/control hash drift, worktree root replacement or reparse, egress or file-change grant, path escape, oversized output, timeout, abort, PID identity mismatch, and cleanup failure. Before native execution these yield launch zero; after launch they yield a failed outcome and never a clean receipt. The optional real probe must prove worktree reads succeed, project writes fail, the owned runtime root is writable, sibling and network access fail, every process is closed, and the original ACL and bytes are restored. Actual checker contract semantics and Cue acceptance are later units.
