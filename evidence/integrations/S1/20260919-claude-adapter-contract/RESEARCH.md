## Smallest real adapter

Use existing `HostCandidate.launch(RuntimeContext)` for **role `implementation`**, returning `AdapterExecution {completion,cancel,durableRef?}`; the host still supplies authorization, current subject, evidence, independent failed-start/finish cleanup receipts, and candidate availability ([runtime interface](../../../../daemon/src/integration-runtime.ts)). Bind `context.accountIdentity`, attempt/run/candidate/subject, owner/envelope, canonical worktree, and exact installation descriptor before spawn. A model-only candidate or a text-only result cannot satisfy S1-03 second-agent coding capability. Do not borrow Codex's typed activity source or native receipt claim ([executor seam](../../../../daemon/src/adapters/integration-executors.ts)).

Launch via `spawnOwned` with exact absolute executable, worktree cwd, **explicit allowlisted environment**, piped stdio, hidden window, and `shell:false`; it owns the initial PID/session row and handles failed registration ([process boundary](../../../../daemon/src/process-launch.ts)). `spawnOwnedPiped` inherits ambient environment and is unsuitable. Start with one `-p` run; pass bounded task prompt through stdin only after verifying print mode's piped-content behavior for this exact version offline or in an authorized probe. Never put prompt/secret in argv, diagnostic logs, or ledger. The protocol argv baseline is `-p --output-format stream-json --verbose --include-partial-messages --permission-prompts none --restricted --tools <approved subset> --disallowedTools mcp__* --no-session-persistence`; `--model` only from verified canonical binding. `--restricted` retains file tools within working directories and removes command/code execution unless explicitly restored; therefore a policy for the permitted coding tools must come from the approved envelope. `--bare` leaves Bash/read/edit available and is not a security boundary. `--safe-mode` disables personal customizations but managed policy still applies. `--settings` only overrides specified keys and cannot erase unspecified file settings. [CLI reference](https://code.claude.com/docs/en/cli-reference).

**Identity/config tension:** Anthropic documents the sign-in session in `~/.claude.json`; `CLAUDE_CONFIG_DIR` relocates Claude settings/session/plugin state. An empty isolated config directory cannot be assumed to preserve the user's existing subscription login. Do not copy credential files or use an ambient home as a hidden fallback. Implement an injectable host credential/config resolver that either supplies an already authorized, version-supported isolated session mechanism, or returns `unauthenticated`/ineligible before spawn. Exact resolver and policy design need separate evidence; reading profile identity/metadata is not login or entitlement proof. [Settings locations](https://code.claude.com/docs/en/settings), [installation contract](../../../../app/provider-installation.mjs).

## Stream and terminal mapping

Official CLI mode emits newline-delimited JSON, and `--include-partial-messages` includes token events. The final line is a `result` with final response, cost, and session metadata. SDK streaming docs distinguish provisional `stream_event` deltas from completed `assistant` messages, which may both appear; do not concatenate both. CLI may emit subagent `assistant`/`user` with `parent_tool_use_id`; don't flatten these into primary text. Parse only documented discriminator structures used by the adapter, preserve unknown metadata privately, and fail closed on an unknown control/terminal or tool event that changes claimed work. Bound bytes, frames, UTF-8, depth, time, stderr, callback lag, and event count; require one terminal, complete EOF, exit 0, no abort, and expected session/model identity for success. Nonzero exit, `result` error subtype, permission denial, max-turn/budget stop, missing terminal, truncation, or protocol mismatch is failed/unknown with raw diagnostic data redacted. Usage is `supported` only when validated final accounting is captured; cost is provider estimate, not settled subscription billing. No observed usage means unknown, never zero. [Programmatic streaming](https://code.claude.com/docs/en/headless), [SDK streaming semantics](https://code.claude.com/docs/en/agent-sdk/streaming-output), [earlier field research](../../20260912-claude-wire-contract-research.md).

`cancel()` requests bounded termination of the owned local process tree and idempotently fences later stdout/callbacks. It does **not** prove local cleanup or stop remote work/billing. Completion and cleanup remain distinct; only `RuntimeHost.verifyCleanup` / `verifyFailedStartCleanup` can issue a cleanup receipt after inspecting process identity and residual resources. Unsupported session resume, tool permission bridging, MCP, subagents, structured outputs, and remote billing finalization should have explicit capability status; they must not be silently presented as supported. A local working-tree diff is evidence of work, not standalone acceptance.

## Next implementable offline unit

Implemented in this turn: [parser](../../../../daemon/src/adapters/claude-cli-protocol.ts) and [focused tests](../../../../daemon/test/integration-claude-cli-protocol.test.ts). It is not imported by the runtime or registered as a candidate. Initial 5/5 and review-corrected 6/6 focused Vitest passes succeeded; root owns the broader build gate. The parser maps only official pinned field names and tolerates extension fields, rejects unrecognized terminal subtypes, separates provisional delta from complete assistant, emits init model/version/cwd for later host comparison, retains tool id/name and parent attribution, validates integer token counts, and exposes provider terminal/estimated usage without claiming process exit, cleanup, or billing. Complete blocks use wrapper/message/parent/block identity; exact replay is idempotent, conflicting replay fails. Its event subset and test data are package-mapped; exact CLI compatibility still requires observation. The earlier proposed executor API below remains unimplemented.

Proposed seam (compile against the existing Cue types, no SDK import or SDK launcher):

```ts
createClaudeCliDecoder(limits): {
  push(chunk: Uint8Array): readonly ClaudeCliProjection[];
  finish(): ClaudeCliTerminal;
}
// Projections: {kind:'delta'|'assistant'|'tool'|'usage'|'error',
// sessionId, messageId?, blockIndex?, parentToolUseId?, ordinal, ...}
createClaudeCliExecutor(host: {
  db: Ledger;
  installation: ProviderInstallationDescriptor;
  resolveAttempt(context: RuntimeContext): {owner: SessionOwner; envelope: Envelope; prompt: string};
  resolveAuthorizedConfig(context: RuntimeContext): ClaudeConfigBinding | null;
  observeEvent(event: AttemptBoundClaudeEvent): void | Promise<void>;
  stopOwnedTree(session: SessionRecord): Promise<void>;
}): (context: RuntimeContext) => Promise<AdapterExecution>;
```

The decoder's `finish()` yields a provider terminal only; the executor combines that terminal with process exit/abort and returns `ExecutionOutcome`. The runtime host, not the adapter, verifies cleanup. `ClaudeConfigBinding` is host-issued proof of an authorized existing subscription configuration path and exact env allowlist, never a Boolean `identityVerified` supplied by a model or UI. Resolve it before spawn; null refuses launch. This API is a design proposal, not an implemented type or compatibility claim.
