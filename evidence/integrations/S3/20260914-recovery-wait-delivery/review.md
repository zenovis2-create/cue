# Independent recovery wait delivery review

## Completion contract (written before review)

Done means a read-only source/test review establishes, with file-and-line evidence, that the real public driver and SQLite store path tests this exact sequence: a cleanly failed old attempt; an approved recovery decision; the root is reopened to `running`; a held replacement is launched with a newly generated attempt identity; a queued response is claimed and delivered only to that replacement's exact `attemptId`, `identityId`, and `durableRef`, with exact content bytes/reference; the old attempt cannot claim or retarget it; replay does not create a second delivery. The fixture must reach the real approval, recovery, deadline, engine, request-queue, and store authorities without directly editing SQLite to manufacture the old/new identity relationship. Claims must be limited to the recovery actions actually exercised; recreating a driver over the same ledger is not called process-restart reconnection.

Attempt cap: 2 review passes. Every pass checks the final source/test preimages, the public `recover`/`applyRecovery` and `pendingRecovery` start path, wait-claim lineage guards, the fixture's setup and assertions, and `git diff` for source scope. A failing pass gets one new source-grounded hypothesis; unchanged failure after two passes is BLOCKED and handed back to the maker.

Gate (only after a stable candidate): `npx vitest run test/integration-driver.test.ts test/integration-request-queue.test.ts test/integration-driver-core.test.ts test/integration-local-driver.test.ts --reporter=verbose --fileParallelism=false --maxWorkers=1`, run from `daemon`; its first raw output and exit code are saved directly under `logs/independent-*`. A regression or weaker oracle is rejected rather than retained.

## Review

Pass 1 source review rejected the first candidate before running the gate. The fixture attempted to append the old attempt's response only after that attempt had reached `failed`; production `request-queue.respond()` revalidates the request's attempt through `current()` and therefore must throw `wait_attempt_unavailable`. The corrected hypothesis is to persist the old response while the old attempt is still running, then claim it only after recovery has launched the replacement. The oracle must also prove distinct old/new attempt, identity, and durable reference; the approved recovery decision/activation; and exact delivered request/response/content reference, digest, and bytes. No source finding required a product change.

Pass 2 reviewed the stable test-only candidate at `daemon/test/integration-driver.test.ts:368-386` and passes it.

The fixture uses the existing real driver, engine, recovery policy, request queue, and in-memory SQLite ledger. It prepares, records the fixture approval event, activates, and starts through public driver methods. The original maker attempt finishes `failed` with `cleanup_verified=1`, and the root is observed `blocked`. Public `driver.recover()` records an approved `retry` at revision 0; the following public `start()` observes the root `running` and a held replacement whose attempt ID, identity ID, and durable reference differ from the failed attempt. No SQL write manufactures either attempt or their relationship. The configured absolute recovery deadline remains unchanged.

The replacement creates and resolves its wait through public driver methods. The first delivery is asserted against the replacement's exact attempt ID, identity ID, durable reference, request ID, response ID, content reference, SHA-256, and content bytes. A second call and a new driver object over the same ledger both return the existing delivered claim without a second host send. This is same-ledger driver recreation only; it does not prove process-restart reconnection. The failed identity is denied a new wait request with `wait_attempt_unavailable`, so it cannot create a request that retargets the held replacement. The fixture does not claim that an old response was queued before failure.

Source inspection agrees with the oracle. `app/orchestration-driver.mjs:333-358` records recovery, resets only the selected failed step, binds `pendingRecovery`, clears the old request/handle, and reopens the blocked root only for public recovery. Lines 375-396 derive the replacement request from the approved decision before engine start. Lines 462-478 claim before external delivery, resolve the claim's persisted attempt to the current owned handle, require the exact root to remain running, and forward the persisted lineage and content. `daemon/src/orchestration/store.ts:298-331` rechecks running attempt/identity/intent integrity and authorities, verifies resolved content bytes, persists one immutable dispatch claim, and accepts `delivered` only for an acknowledgement matching its attempt, identity, durable reference, and content digest. `daemon/src/request-queue.ts:37-58` rejects wait activity for a failed identity. No product defect was found and production source was untouched by this unit; the driver preimage and final driver hash are identical.
