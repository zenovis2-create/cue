# Two-approval UI/IPC implementation result

Added explicit planning availability and two preparation channels through IPC/preload. Planning preparation accepts only `{goal,autonomy,selectionMode}`; conversion accepts only `{planningRunId,autonomy,selectionMode}`. Exact own plain fields, bounds, and trusted sender checks prevent renderer proposal text or arbitrary authority fields from entering Core. Existing general and JSON preparation remain distinct.

The real renderer exposes planning only when `planningAvailability().available` is true. First approval starts the planning run. Only a completed planning card with `planning.readyForExecution===true` and released execution ownership reveals the conversion action; it calls Core with the planning run ID. The execution response must report `phase:'execution'` and the matching `sourcePlanningRunId`, then a fresh approval click starts that separate run. The approval plan, status card, and stop controls are reused.
