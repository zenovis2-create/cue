# Read-only recovery API evidence

2026-09-11, root. Preparatory primary-source check only; no implementation or OS query. Completion is source attribution and explicit unknown/error handling, not a runtime PASS. This supplements the [local reuse note](20260911-native-recovery-reuse.md).

- `OpenProcess` returns a null handle on failure. The official page explicitly documents invalid-parameter for PID0 and access-denied for protected system processes; it does not establish a general missing-process rule for every failure. Do not turn an arbitrary error into absence. [Microsoft OpenProcess](https://learn.microsoft.com/en-us/windows/win32/api/processthreadsapi/nf-processthreadsapi-openprocess).
- The local `Process.GetProcessById(Int32)` overload documents ArgumentException for a process that is no longer running. A future helper could use this narrow local lookup as separately classified corroboration; other exceptions remain unknown. A returned Process object alone is not proof of matching creation time or liveness. [Microsoft GetProcessById](https://learn.microsoft.com/en-us/dotnet/api/system.diagnostics.process.getprocessbyid?view=netframework-4.8.1).
- `GetProcessTimes` accepts query or limited-query access and returns a 64-bit FILETIME creation value. Retain exact integer precision, compare against the recorded value, and do not read undefined exit-time content for a still-running process. [Microsoft GetProcessTimes](https://learn.microsoft.com/en-us/windows/win32/api/processthreadsapi/nf-processthreadsapi-getprocesstimes).
- `WaitForSingleObject(handle,0)` checks state without waiting and requires SYNCHRONIZE. Distinguish signaled, timeout and failure on the same still-open process handle; close it after the query. These classifications do not authorize cleanup or execution restart. [Microsoft WaitForSingleObject](https://learn.microsoft.com/en-us/windows/win32/api/synchapi/nf-synchapi-waitforsingleobject).
