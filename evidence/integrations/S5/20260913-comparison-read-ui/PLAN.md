# Saved comparison read UI maker plan

## Done contract

Done means a caller can submit the exact historical `{ operation: 'comparison-read', snapshotId }` command before preparing a run, the existing workspace-scoped Core read is projected through a strict bounded descriptive DTO, and the existing evaluation panel renders only fixed Korean status/count language with explicit unmeasured, insufficient, statistically unqualified, and promotion-not-allowed limits. Existing enrollment, observation, and coverage operations remain bound to the current prepared run. No comparison, trial, policy, approval, execution, model, provider, native, network, or report state is created or changed.

## Attempt cap

At most two corrections per diagnosed issue. A failed pass must produce a new hypothesis before another edit. Keep no change that worsens the focused gate.

## Per-pass evidence

Run from `daemon/`:

`npm exec vitest run -- test/integration-evaluation-ui.test.ts test/integration-evaluation-comparisons-core.test.ts --reporter=dot --fileParallelism=false --maxWorkers=1`

Then run `npm run build`, `node --check ../app/ipc.mjs`, and `node --check ../app/renderer/renderer.js`. Inspect the scoped diff and record final hashes.

## Failure handoff

If the cap is exhausted, stop changing that issue and record the attempted hypotheses, exact failures, and remaining blocker for independent review. No live Electron, local server/model, provider, native helper, or network fallback is allowed.

## Copy-only addendum

Done means the new comparison UI replaces internal terms `투영`, `trial`, and `기술적 기록` with plain Korean saved-record and measurement language while preserving every field, count, guard, layout, and behavior. The focused two-suite gate and both JavaScript syntax checks must remain green. No TypeScript source changes or build rerun are required for this wording-only correction.
