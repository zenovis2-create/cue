## Blocking finding

The canonical R-08 row lists `app/core.mjs` in `cueProductBytes` at SHA-256:

`c71d66f7c979487445abab4088da138864011f259488f5097660cb397fe7c70f`

The current frozen `app/core.mjs` hashes to:

`2379aa122c64e8d891d7e8b844d400d2a14aa7256d4f984333b6ab73dd4df096`

Despite that mismatch, the exact consumer command still exits 0 and prints `verified byte-for-byte`:

```text
node scripts/reuse/reuse-fixture-receipts.mjs --verify evidence/integrations/S0/20260916-selected-lifecycle-matrix/receipts
```

The cause is in `readSelectedReuseBasis`: the R-08 branch validates the shape of `cueProductBytes` and includes those values in the canonical selection digest, but it does not call the filesystem `verify()` function for each reference. R-04/R-05/R-06 do verify their descriptors and selected bytes. The current test mutates the R-08 commit, but it does not mutate a referenced R-08 Cue consumer file or its bound hash.

Consequently, the R-08 boundary row's `executed-hash-bound-selection` label is not true for current source. A stale catalog and stale receipt can pass the actual CLI consumer. Since the task requires valid current selected-set source references, this is a concrete R03 evidence gap.
