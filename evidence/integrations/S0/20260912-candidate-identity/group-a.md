## `agy` — Google Antigravity CLI

### Exact identity and organization

- **Canonical identity:** Antigravity CLI, invoked as `agy`. The repository README links to Google’s official product documentation and says the CLI brings Antigravity’s shared agent harness to the terminal ([pinned README](https://github.com/google-antigravity/antigravity-cli/blob/e4afe6b6f3aa115b1ba31e26db6508a23b5e42e5/README.md)); the [official overview](https://antigravity.google/docs/cli/overview) independently describes it as Antigravity’s lightweight TUI.
- **Publisher/organization:** public GitHub organization `google-antigravity`, with Google-hosted documentation at `antigravity.google`. This is sufficient first-party evidence for the product mapping; it should not be confused with third-party `agy-*` wrappers.
- **Inspected revision:** tag/release **1.2.1**, commit [`e4afe6b6f3aa115b1ba31e26db6508a23b5e42e5`](https://github.com/google-antigravity/antigravity-cli/commit/e4afe6b6f3aa115b1ba31e26db6508a23b5e42e5), committed and published **2026-09-11 UTC** ([release](https://github.com/google-antigravity/antigravity-cli/releases/tag/1.2.1)). The live docs navigation still labels the CLI documentation `v1.2.0`, so the pinned 1.2.1 changelog is the newer release record.

### License and redistribution

- **License file/SPDX:** none at the inspected repository root, and GitHub repository metadata reports no detected license (`license: null`) ([repository API](https://api.github.com/repos/google-antigravity/antigravity-cli), [pinned repository tree](https://github.com/google-antigravity/antigravity-cli/tree/e4afe6b6f3aa115b1ba31e26db6508a23b5e42e5)). Therefore there is **no SPDX license grant established by this public repository**.
- **Redistribution caveat:** public download/source visibility alone does not establish permission to redistribute or modify the CLI. Treat it as a vendor binary governed by the linked Google terms, and do not vendor or redistribute it unless a separate applicable license/contract is identified. The README also says use permits collection of interaction data by default with an opt-out in settings and links the Google terms/privacy policy ([pinned README](https://github.com/google-antigravity/antigravity-cli/blob/e4afe6b6f3aa115b1ba31e26db6508a23b5e42e5/README.md#terms-of-service--data-use)).

### Role and public control surface

- **Role:** terminal coding-agent harness: multi-step reasoning, multi-file editing, tool calls, persistent conversation history, background tasks/subagents, and orchestration. It is a CLI/TUI backed by hosted models, not a standalone model.
- **Process control:** `agy -p`/`--print`/`--prompt` performs a single headless turn. `--output-format json` emits one result envelope; `stream-json` emits NDJSON `init`, `step_update`, and terminal `result` events. `--json-schema` provides structured output. A long-lived process can accept NDJSON user events on stdin with `--input-format stream-json`, but only text content blocks are supported ([official headless documentation](https://antigravity.google/docs/cli/headless/)).
- **Conversation control:** `--continue` resumes the most recent conversation and `--conversation <id>` selects one; each ordinary invocation is a new process, while stream-input mode keeps one process warm ([official headless documentation](https://antigravity.google/docs/cli/headless/)).
- **MCP relationship:** Antigravity CLI is an MCP **client/host** for configured external servers, not itself identified as an MCP server by the inspected CLI materials. Release 1.2.1 improves MCP provider schema handling, and the [pinned changelog](https://github.com/google-antigravity/antigravity-cli/blob/e4afe6b6f3aa115b1ba31e26db6508a23b5e42e5/CHANGELOG.md#121) is the relevant versioned evidence.

### Authentication, Windows/runtime, and side effects

- **Authentication reference approach:** first interactive launch uses the system keyring when possible and otherwise opens Google Sign-In; remote/SSH use prints an authorization URL. Headless mode uses cached credentials and unauthenticated no-terminal runs exit with `authentication required`. Enterprise onboarding can connect a GCP project ([pinned README](https://github.com/google-antigravity/antigravity-cli/blob/e4afe6b6f3aa115b1ba31e26db6508a23b5e42e5/README.md#authentication), [official headless docs](https://antigravity.google/docs/cli/headless/)). An integration should reference an existing authenticated profile rather than capture or copy credentials.
- **Windows/runtime:** official fast-path installers are supplied for macOS/Linux, Windows PowerShell, and Windows CMD. The Windows installer registers `agy` under `C:\Users\<username>\AppData\Local\agy\bin`; macOS/Linux uses `~/.local/bin/agy` ([official getting-started guide](https://antigravity.google/docs/cli/getting-started)). No separate language runtime prerequisite is stated for the released binary.
- **Install/runtime side effects:** installer execution downloads/registers the executable in PATH. First launch writes preferences/trust state and indexes the selected workspace. The changelog documents centralized CLI state below `~/.gemini/antigravity-cli/` and shared plugin materialization below `~/.gemini/config/` ([pinned changelog](https://github.com/google-antigravity/antigravity-cli/blob/e4afe6b6f3aa115b1ba31e26db6508a23b5e42e5/CHANGELOG.md)). These paths are evidence of runtime state, not a complete installer manifest.

### Unsupported/limited conditions and maintenance

- First-time sign-in is not an unattended headless flow; authenticate interactively before CI/headless use. Stream-input accepts text blocks only. The public repository contains documentation/examples and release artifacts but no visible source tree or license file, so source-level embedding or rebuilding cannot be assumed from this repo.
- **Maintenance signal:** release 1.2.1 and HEAD were published/committed on 2026-09-11, one day before inspection. The pinned changelog records active fixes to model retries, MCP schemas, conversation resume, rendering, and remote-control authentication. This is active maintenance, while the docs version-label lag should be accounted for.

## `grok build` — SpaceXAI Grok Build

### Exact identity and organization

- **Canonical identity:** Grok Build, installed/invoked as `grok`; canonical repository [`xai-org/grok-build`](https://github.com/xai-org/grok-build). Its README calls it SpaceXAI’s terminal AI coding agent and states that this repository is periodically synced from the SpaceXAI monorepo ([pinned README](https://github.com/xai-org/grok-build/blob/37949780c144e37df692e3d669051a21fec24f20/README.md)).
- **Publisher/organization:** `xai-org` / SpaceXAI. Official product docs are at [docs.x.ai/build/overview](https://docs.x.ai/build/overview).
- **Inspected revision:** repository HEAD [`37949780c144e37df692e3d669051a21fec24f20`](https://github.com/xai-org/grok-build/commit/37949780c144e37df692e3d669051a21fec24f20), committed **2026-09-09 UTC**; embedded monorepo `Source-Revision` is `c4ea71cfdbcdb21e32e41bc25a0043d7d4836714` in the commit message and [`SOURCE_REV`](https://github.com/xai-org/grok-build/blob/37949780c144e37df692e3d669051a21fec24f20/SOURCE_REV). The repository had **no GitHub tags or GitHub releases** at inspection, so no tag is assigned to this snapshot.

### License and redistribution

- **License file/SPDX:** first-party code is **Apache-2.0**, declared in the [pinned LICENSE](https://github.com/xai-org/grok-build/blob/37949780c144e37df692e3d669051a21fec24f20/LICENSE) and README.
- **Redistribution caveat:** third-party and vendored code keeps its original licenses. A redistribution must inspect and preserve the applicable notices in [`THIRD-PARTY-NOTICES`](https://github.com/xai-org/grok-build/blob/37949780c144e37df692e3d669051a21fec24f20/THIRD-PARTY-NOTICES), the tools crate’s notice, and `third_party/NOTICE`, including the documented Apache section 4(b) change notice. External contributions are not accepted ([pinned CONTRIBUTING](https://github.com/xai-org/grok-build/blob/37949780c144e37df692e3d669051a21fec24f20/CONTRIBUTING.md)); that project policy is distinct from the Apache redistribution grant.

### Role and public control/API/protocol surface

- **Role:** coding-agent CLI/TUI plus agent runtime/orchestrator. It edits files, runs commands, searches the web, uses skills/plugins/hooks/MCP, manages sessions, subagents, worktrees, and long-running tasks. It is not equivalent to the separately callable Grok model API ([official overview](https://docs.x.ai/build/overview)).
- **Headless subprocess surface:** `grok -p` supports `plain`, `json`, `streaming-json`, and `streaming-messages-json`. The native stream is derived from ACP session updates; the Messages-shaped stream contains documented fidelity limitations and is read-only. Tool allow/deny lists, max turns, agents, permission rules, and session resume are exposed as flags ([pinned headless guide](https://github.com/xai-org/grok-build/blob/37949780c144e37df692e3d669051a21fec24f20/crates/codegen/xai-grok-pager/docs/user-guide/14-headless-mode.md)).
- **Long-lived protocol:** `grok agent ... stdio` speaks **Agent Client Protocol (ACP) over JSON-RPC 2.0** for IDEs, SDKs, eval harnesses, and custom apps. ACP supplies sessions, streaming updates, tool calls, permissions, and MCP server configuration; Grok adds `x.ai/*` extension methods. A WebSocket server mode is also documented with secret-token authentication ([pinned agent-mode guide](https://github.com/xai-org/grok-build/blob/37949780c144e37df692e3d669051a21fec24f20/crates/codegen/xai-grok-pager/docs/user-guide/15-agent-mode.md)).
- **MCP relationship:** Grok is an MCP client/host. It supports local stdio and remote HTTP/SSE servers, CLI management (`grok mcp ...`), OAuth for remote servers, project/user scopes, and compatibility imports. It exposes MCP tools to the agent; this is separate from ACP, which controls Grok itself ([pinned MCP guide](https://github.com/xai-org/grok-build/blob/37949780c144e37df692e3d669051a21fec24f20/crates/codegen/xai-grok-pager/docs/user-guide/07-mcp-servers.md)).

### Authentication, Windows/runtime, and side effects

- **Authentication reference approach:** default browser OAuth at `auth.x.ai`, cached at `~/.grok/auth.json`; device-code flow supports remote/headless environments. `XAI_API_KEY` is a fallback only when no active session token exists. Enterprise OIDC and an external auth-provider command are also documented. MCP OAuth credentials are separate at `~/.grok/mcp_credentials.json` ([pinned authentication guide](https://github.com/xai-org/grok-build/blob/37949780c144e37df692e3d669051a21fec24f20/crates/codegen/xai-grok-pager/docs/user-guide/02-authentication.md)). Integrations should select one documented provider and reference environment/config paths, never copy cached tokens.
- **Windows/runtime:** official prebuilt releases target macOS, Linux, and Windows. PowerShell installation adds `%USERPROFILE%\.grok\bin` to the user PATH; Git Bash/MSYS2 and WSL paths are also documented. Building this source requires the pinned Rust toolchain, DotSlash (which can download hermetic tools), and `protoc`; macOS/Linux are supported build hosts, while Windows builds from this tree are best-effort and untested ([pinned README](https://github.com/xai-org/grok-build/blob/37949780c144e37df692e3d669051a21fec24f20/README.md), [pinned getting-started guide](https://github.com/xai-org/grok-build/blob/37949780c144e37df692e3d669051a21fec24f20/crates/codegen/xai-grok-pager/docs/user-guide/01-getting-started.md)).
- **Install/runtime side effects:** the installer downloads a binary, writes beneath `~/.grok`/`%USERPROFILE%\.grok`, and modifies user PATH on Windows. Runtime persists auth, MCP credentials, configuration, sessions, memory, plugins/skills, logs, and project-scoped `.grok/config.toml` when requested. MCP stdio servers spawn child processes; source builds may cause `rustup` and DotSlash downloads.

### Unsupported/limited conditions and maintenance

- Building from this public source on Windows is explicitly untested/best-effort. Headless JSON streams cannot conduct bidirectional approval flows; use ACP for that. The Messages-compatible stream documents incomplete/zero-filled usage and other fidelity limitations, so consumers must not interpret every zero as actual zero. External pull requests are unsupported.
- **Maintenance signal:** the inspected sync commit is dated 2026-09-09 and includes a long list of runtime, MCP, agent-host, memory, and UI changes. The repo states it is periodically synced from a monorepo. There are no public GitHub issues, pull requests, tags, or releases enabled, which limits public maintenance history even though the source snapshot is recent.
