# Phase 10 — 실제 엔진 연결 (P10-1 ~ P10-12)

Phase 9로 앱 껍데기와 안전 배관이 섰다(174 통과 / 5 스킵, 커밋 `6cd3271`).
그러나 **앱은 아직 일을 하지 않는다.** `app/core.mjs`의 `execute()`가 `cue-p9-live.txt`를 직접 쓰고, `allowed_actions`도 그 파일 하나로 고정돼 있다. 무슨 목표를 입력하든 결과가 같다.

Phase 10은 **`execute()`가 하드코딩 대신 실제 코딩 에이전트를 봉투 안에서 기동**하도록 잇는다.

여기서 가장 위험한 실패는 **일하는 척하는 것**이다.
목표를 받아 그럴듯한 카드를 띄우면서 실제로는 아무 워커도 안 도는 앱은, 지금까지 아홉 단계 쌓은 검증 규율을
**전부 무의미하게 만든다.** 이 Phase의 모든 검사는 "정말로 돌았는가"를 향한다.

## 판정 규칙

- `PASS` — 검사가 실제로 통과. `PARTIAL` — 일부만(**PASS 아님**). `FAIL` / `SKIPPED`(이유 필수).
- **기존 테스트(p1~p9, release)를 수정하거나 삭제하지 마라.** 단정 약화는 FAIL이다.
- **PARTIAL 3건(P3-16, P4-2, P6-3)을 PASS로 올리지 마라.**
- **외부 상태를 바꾸지 마라** — 게시·릴레이 전송·계정 등록 금지. 작업은 임시 worktree 안에서만.

## P10-1 하드코딩 제거

- 검사: `app/` 전체에 `cue-p9-live.txt` 문자열이 **0건**.
- 검사: `allowed_actions`가 목표에서 도출된다. 고정 리터럴이 아니다.

## P10-2 실제 에이전트 기동

- `execute()`가 `spawnVendorCodexInAppContainer(db, owner, ...)` 경로로 실제 워커를 띄운다.
- 검사: 실행 후 원장에 **실제 세션/실행 레코드**와 **실제 PID**가 남는다.
- 검사: `writeFileSync`로 결과물을 직접 만드는 경로가 `app/`에 **0건**.

## P10-3 **서로 다른 목표 2개 → 서로 다른 결과** — 이 Phase의 핵심

- 목표 A와 목표 B(내용이 다른 두 작업)를 **각각 실기동**하라.
- 검사: **산출물이 서로 다르다.** 파일명·내용이 목표를 반영한다.
- 검사: 두 실행의 봉투가 서로 다르다(`allowed_actions`가 다름).
- 검사: 두 실행의 PID가 서로 다른 실제 프로세스다.
- **한 목표만 돌리고 통과시키지 마라.** 결과가 같으면 FAIL이다.

## P10-4 실행 중 중단이 실제로 죽인다

- 실행 중 `중단`을 눌렀을 때 **실제 워커 프로세스가 종료**된다.
- 검사: 중단 전 PID가 살아 있고, 중단 후 그 PID가 **없다**.
- 검사: 원장 상태가 중단으로 남는다. 조용히 완료로 적지 마라.

## P10-5 봉투 밖 쓰기 차단 — 실기동

- 에이전트가 봉투 밖 경로에 쓰려 하면 **차단**된다.
- 검사: 실제 AppContainer 안에서 시도하고, 바깥 파일이 **생성되지 않음**을 확인.
- 검사: 위반이 원장에 `blocked/violation`으로 남는다.

## P10-6 금지된 네트워크 차단 — 실기동

- 봉투가 네트워크를 불허하면 요청 시 **즉시 중단**된다.
- 검사: 실제 시도 후 중단 관측.
- **주의**: P3-16은 **탐지 후 중단**이며 syscall 강제가 아니다. 이 사실을 바꿔 적지 마라. 관측한 그대로 등급을 적어라.

## P10-7 진행 상태가 실시간으로 보인다

- 검사: 실행 중 상태가 `작업 중`이고, 완료 후 `완료`로 바뀐다.
- 검사: 상태값이 **원장에서 온다**. 타이머로 흉내 내지 마라.

## P10-8 복구 사다리가 앱에서 실제로 돈다

- 실패하는 작업을 하나 골라 자율성 ③으로 돌려라.
- 검사: **자동 복구가 실제로 시도된다**(카드의 `자동 복구 N회`가 0이 아니게 된다).
- 검사: 재시도 상한 도달 후 사람에게 넘어간다. 무한 재시도 금지.
- 검사: 자율성 ①로 같은 작업을 돌리면 복구 시도 0회.

## P10-9 승인 게이트 유지

- 검사: 승인 없이 `execute`가 여전히 거부된다(P9-3 규칙 불변).
- 검사: 봉투는 실행 중 수정 불가. 넓히려면 중단 후 새 승인.

## P10-10 자격증명 미주입

- 검사: 워커 환경에 자격증명이 전달되지 않는다. 로그·원장에도 남지 않는다.

## P10-11 침묵 규율 유지

- 검사: 실제 작업 진행 중 알림 방출 0건. 막힘·완료 때만 보고.

## P10-12 회귀

- 검사: 기존 174 통과 / 5 스킵이 **줄지 않는다.**
