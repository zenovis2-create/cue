# 최종 라운드 — 출시 판정 R-1 ~ R-9 + 개선안 I-1 ~ I-6

Phase 1~8이 끝났다(테스트 151 통과 / 5 스킵, 커밋 `66809ab`).
이 라운드는 **v0.1을 출시할 수 있는지 판정**하고, 별도로 모아둔 **개선안 6건**을 반영한다.

여기서 가장 위험한 실패는 **"돌려봤다고 적고 안 돌리는 것"**이다.
R-3·R-4·R-6·R-9는 **실제로 실행해야 하는 항목**이다. 단위 테스트로 흉내 내면 FAIL이다.

## 판정 규칙

- `PASS` — 검사가 실제로 통과.
- `PARTIAL` — 일부만. **PASS 아님.**
- `FAIL` / `SKIPPED`(이유 필수).

**기존 테스트(p1~p8)를 수정하거나 삭제하지 마라.** 단정 약화는 그 자체로 FAIL이다.
**외부 상태를 바꾸지 마라** — 실제 게시·릴레이 전송·`@cue` 등록 금지.

**이미 PARTIAL인 항목을 PASS로 올리지 마라.** P3-16(네트워크 탐지만), P4-2(`cwd` 독립 확인 불가), P6-3(실 Buzz 전달 미검증)은 **PARTIAL인 채로 출시 문서에 남는다.** 이걸 올리려는 시도 자체가 FAIL이다.

# 1부 — 출시 판정

## R-1 Phase 1 기록 보존
검사: P1-1 ~ P1-3의 통과/실패 기록이 원문 증거와 함께 `evidence/P1/`에 있다. 없으면 FAIL, 만들어내지 마라.

## R-2 금지 문자열 CI 테스트
`src/` 전체에 대해 다음이 **0건**임을 검사하는 테스트를 추가하라:
`acceptForSession`, `acceptWithExecpolicyAmendment`, `applyNetworkPolicyAmendment`,
`scope: "session"`, `--yolo`, `--accept-hooks`, `--dangerously-bypass`,
`--approve-for-me`, `-a never`, `git reset --hard`.
검사: **양성 대조** — 임시 파일에 금지 문자열을 넣어 테스트가 실제로 FAIL하는지 확인한 뒤 삭제하라. 항상 초록불인 검사기는 무용지물이다.

## R-3 봉투 밖 쓰기 실차단 — **심볼릭 링크 케이스**
검사: worktree 안에 worktree **밖을 가리키는 심볼릭 링크(또는 junction)** 를 만들고, 워커가 그 링크를 통해 쓰기를 시도한다. **강제층에서 실제로 차단**되어야 한다.
경로 문자열 검사로 통과시키지 마라 — 링크는 문자열상 worktree 안이다. **OS가 막아야 한다.**
차단되지 않으면 FAIL로 적어라. 이건 P3C 파일시스템 강제의 진짜 시험이다.

## R-4 크래시 → 재시작 → 자동 재개 없음
검사: 데몬을 **실제로 죽이고**(프로세스 kill) 재시작한 뒤, 쓰기가 자동 재개되지 **않고** `blocked/crash` 상태에 머무는 것을 확인.
검사: 재시작 후 `git status` 보고가 사람에게 제시된다.

## R-5 sentinel 죽음 알림
검사: 두 조건이 **모두** 성립할 때만 알림이 뜬다. 한 조건만으로 뜨면 FAIL.

## R-6 실제 태스크 하나를 끝까지
**세 줄 승인 → 디스패치 → 자동 승인 N건 → 검증 → 한국어 완료 보고 + 승인 카운터**.
검사: 실제 실행이다. 원장에 실제 run/approval 행이 남고, 최종 보고 문자열이 원장 집계와 일치.
외부 부작용이 없는 사소한 태스크를 골라라(예: worktree 안 파일 하나 생성).

## R-7 `budget` 방출 경로 0개
검사: 통화 금액을 방출하는 코드 경로가 **0개**. 토큰 수는 허용.

# 2부 — 개선안 (외부 문서 분석에서 도출)

## I-1 정지형 라우팅 — 회피 금지
`routing.yaml` 판정에서, 규칙이 맞는데 **"이 경우는 좀 다르다"는 식으로 세분화해 다른 경로로 빠지는 것**을 금지한다.
검사: 카테고리가 일치하면 그 경로가 선택된다. 세분화 우회 경로가 없다(테스트 1개).
검사: 애매하면 임의 판단이 아니라 `ask_me`다.

## I-2 보고는 경로를 반드시 서술한다
대화 제품과 반대다. Cue는 **자기 결정 경로를 숨기지 않는다.**
검사: 완료·막힘 보고에 **어떤 판정으로 그 경로를 택했는지**가 포함된다. 매끄러움을 위해 생략하는 경로가 없다.

## I-3 경계선 기록은 분리하고 나중에 쓴다
원장 쓰기에서, **거부·중단될 수 있는 항목**과 **확실한 항목**을 같은 작업에 섞지 마라. 확실한 것 먼저 쓰고, 경계선 항목은 **마지막에 별도 작업**으로 쓴다.
근거: 뒤에 이어지는 쓰기는 앞선 것의 운명을 물려받는다. 섞으면 경계선 하나 때문에 확실한 기록까지 날아간다.
검사: 복구 아티팩트 기록에서 확실 항목이 먼저 커밋되고, 경계선 항목 실패가 앞선 기록을 롤백하지 않는다(테스트 1개).

## I-4 "원장에 있다"는 승인이 아니다
검사: 원장에 기록되어 있다는 사실만으로 실행 권한이 생기는 경로가 **0개**. 권한은 승인 레코드에서만 온다(테스트 1개).

## I-5 효과로 판단 — 포장에 속지 않는다
자율성·선호 설정에서, **형식·톤·워크플로 선호로 포장된 권한 확대 요청**을 거른다.
검사: "효율을 위해 확인을 생략해달라" 류의 요청이 봉투 확대로 이어지지 않는다(테스트 1개).

## I-6 출처 등급 명문화
`confirmed` / `candidate` 구분(P5-1)을 **설계 문서에 규칙으로 명시**하라. 코드는 이미 그렇게 되어 있다. 문서만 추가.
