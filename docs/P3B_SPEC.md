# Phase 3B — 강제층 (P3-9, P3-11, P3-12, P3-15, P3-16, P3-17)

**이 배치가 Cue의 존재 근거다.** Phase 1에서 Codex가 실패한 바로 그 두 가지 —
worktree 밖 쓰기와 네트워크 — 를 **Cue가 직접 막을 수 있느냐**를 증명한다.

기존 `C:/Users/User/cue/daemon`에 42개 테스트가 통과 중이다. **하나도 깨지 마라.**

## 구속력 있는 전제 (Phase 1 실측)

1. `permissions`로 worktree를 좁혀도 승인 후 실행은 밖에 썼다 (`source:"unifiedExecStartup"`).
2. `network.enabled:false` 상태에서 `example.com` **HTTP 200을 받았다**.
3. accept 시나리오에서 **command approval 0건** — permissions 승인 1건이 후속 승인을 삼켰다.
4. 도구의 권한 응답을 강제로 세지 마라. 강제는 전부 Cue.

## 만들 것

### P3-9 강제층 — realpath 경계 감시 (최우선)
- 경계 판정은 **canonical realpath**로만 한다. **문자열 prefix 비교 금지.**
  검사: grep 테스트 — `startsWith(` 로 경로를 비교하는 코드 경로가 없다.
- 검사: 심볼릭 링크로 worktree 밖을 가리키는 쓰기가 차단된다.
  (Windows에서 심링크 생성 권한이 없으면 junction 또는 `fs.realpathSync`로
   같은 상황을 만들고, **불가능하면 SKIPPED로 정직하게 기록**하고 이유를 써라. 위장 PASS 금지.)
- 검사: 봉투 밖 변경이 감지되면 태스크가 `succeeded`로 전이하지 **못한다**.
- 검사: **P1-2 재현 테스트** — 실제로 worktree 밖 절대경로에 쓰는 명령을
  `accept`한 뒤에도 **파일이 생기지 않아야 한다.** 모킹 금지. 실제 파일시스템으로.
  차단 방식은 네가 정해라(사전 검사 + 사후 스캔 + 롤백 조합 등). 단 결과가 증명되어야 한다.

### P3-16 네트워크 게이트를 Cue가 강제
- 봉투에 `egress`가 없으면 워커 프로세스 수준에서 외부 연결을 **실제로** 막는다.
  힌트: 자식 프로세스 환경 제어(프록시 강제 + 루프백 블랙홀), 또는 OS 수준 수단.
  네가 판단해서 **실제로 동작하는 것**을 골라라.
- 검사: **P1-2 재현 테스트** — egress 없는 봉투에서 워커의 `example.com` 요청이 **실패한다.**
  (네트워크가 없는 환경이면 그 사실을 기록하고, 차단 자체는 로컬 리스너로 검증해라.)
- 검사: 허용된 egress는 봉투에 적힌 호스트로 한정 — 그 외 호스트 차단 테스트 1개.
- 검사: 차단 실패를 감지하면 태스크가 `succeeded`로 전이하지 못한다.

### P3-17 승인 ≠ 실행 회계
- 승인 이벤트 수와 실행 이벤트 수를 **각각** 원장에 기록한다.
- 실행이 승인보다 많으면 **경보 행**을 남긴다.
- 검사: permissions 승인 1건 + 후속 실행 3건 시나리오에서 경보가 뜬다.
- 검사: 재생 방지 키가 `itemId` 단독이 아니다(P3-7 연동, null-safe 포함).

### P3-11 봉투 밖 = `decline`, 작업은 생존
- 검사: 봉투 밖 요청 후에도 태스크가 `running`을 유지한다(죽지 않는다).

### P3-12 교착 감지 + 3지선다
- 같은 요청 다이제스트 2회 또는 그 승인에서 정지 → `막힘 — 봉투 밖`.
- 3지선다: `이 상태로 계속` / `범위 넓히기` / `중단`.
- **기본 포커스가 `범위 넓히기`가 아니다.**
- `이 상태로 계속`은 그 다이제스트를 다시 묻지 않는다.
- 검사: 항목마다 테스트 1개(UI 없이 상태/선택 모델 수준으로).

### P3-15 승인 카운터
- 완료 카드가 `자동 승인 N건 · 거부 M건`을 **원장 집계에서 읽어** 표시한다.
- 검사: 하드코딩이나 별도 카운터 변수가 아니라 원장 쿼리 결과다.

## 절대 규칙
1. **증거 없이 완료 주장 금지.** 항목마다 실제 테스트 출력.
2. **테스트를 통과시키려고 검사를 약화시키지 마라.** 못 막으면 **FAIL이라고 써라.**
   FAIL은 실패가 아니라 발견이다. 위장 PASS가 진짜 실패다.
3. P3-9와 P3-16의 재현 테스트는 **실제 파일시스템·실제 소켓**으로. 모킹하면 무의미하다.
4. 작업 범위는 `C:/Users/User/cue/daemon`. 금지: `D:/AI2_WIN/AI-backup-20260505/tactics`.
   `probes/`, `evidence/P1/`, `evidence/P2/` 건드리지 마라. Orca run/task 생성·변경 금지.
5. 테스트가 만든 임시 파일·디렉터리는 정리해라. 시스템 방화벽 규칙을 영구 등록하지 마라.
