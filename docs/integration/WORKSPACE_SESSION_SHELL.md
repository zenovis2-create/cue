# 프로젝트·작업 세션 UI 첫 단계

2026-09-23 / batch100. Cue의 기본 화면을 프로젝트와 작업 세션 중심으로 분리한다. 왼쪽에는 현재 프로젝트와 최근 실행 목록, 가운데에는 기존 목표·범위 승인, 세션 기록은 별도 읽기 화면, 평가·관리 기능은 별도 탐색 영역에 놓는다. dark UI, 키보드 focus와 bounded text projection을 사용한다. 이 레이아웃은 기존 승인/Stop/격리 권한을 바꾸지 않는다.

`cue:workspace-sessions`는 **현재 승인된 worktree와 정확히 일치하는 저장된 run**만 최대20개씩 조회한다. cursor는 같은 worktree의 rowid여야 한다. 상세는 같은 run의 목표 기록과 저장 상태만 돌려준다. 실행, 재연결, 재개, 현재 OS/원격 정리·청구 판정은 하지 않는다. 지금의 '작업 세션'은 **run 하나의 이력 항목**이지 공급자 session_handle이나 여러 run의 지속 대화가 아니다. 이 화면에서 과거 세션을 클릭해도 현재 실행·승인·선택된 평가 run이 바뀌지 않는다. 새 작업은 현재 활성/승인 대기 중인 준비를 조용히 버리지 않는다.

현재 Core와 `cue-config.json`은 시작 시 단일 worktree에 고정되어 있다. 따라서 이 단계에서 프로젝트 카드는 **현재 프로젝트 확인**만 제공하며 추가/전환/삭제를 가장하지 않는다. 진짜 다중 프로젝트는 소유 runtime 정리·writer lease·Core/daemon/IPC 교체·설정 원자 저장·비동기 응답 격리와 충돌/실패 복구를 별도 설계/실측한 뒤 연결해야 한다. 세션 이어쓰기 또한 새 봉투/정책 승인 경계와 공급자 재연결 자격 없이 제공하지 않는다.

개발 검증은 실제 SQLite/Core→IPC와 JSDOM 화면 탐색, 동일/다른 worktree 분리, 재열기, getter/proxy/과다 필드 거부를 포함한다. Chromium file:// 정적 화면 캡처는 시각 참고일 뿐 Electron native/assistive 사용자 인수가 아니다. 공급자 호출은 없다.
