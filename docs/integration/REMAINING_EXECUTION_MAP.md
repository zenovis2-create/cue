나머지 11행은 아래 원본 baseline을 출발점으로 삼고 현재 판정은 위 overlay를 따른다. R03/R04/R05·S2-02·S3-01·S4-05의 완료 범위는 독립 검토에 명시했다. 승인된 기존 파일의 native 구현 도구/스냅샷 계약을 연결했으며 기본 앱의 배포 권한 구성, 실제 공급자 자격 및 동결 holdout 네 모드 개선은 남아 있다. backend 완료를 실제 청구·공급자 자격·성과 개선으로 확장하지 않는다.

분류는 다음과 같다. `offline-now`는 현재 소스와 합성 fixture로 구현·회귀 검증할 수 있다. `live-required`는 실제 provider/OS/Electron 경계가 최종 판정에 필요하다. `external-input`은 신뢰할 수 있는 identity, 가격, entitlement, license 자료가 먼저 필요하다. `deferred-unknown-sha`는 더 이상 열린 분류가 아니다: Codex 실행 파일 SHA의 출처를 npm published integrity·SLSA provenance attestation·tarball 실행 파일·설치 바이트·Authenticode 서명의 한 체인으로 확인해 핀을 `be96b992…`로 갱신했다([batch78 독립 검토](../../evidence/integrations/S0/20260917-identity-auth-protocol/REVIEW.md)). 이 출처 확인은 인증 성공·entitlement·쿼터·청구를 뜻하지 않는다. 로컬 모델은 OFF이며 접속·재시작·다운로드하지 않는다. 기존 구독 계정의 승인된 4회 실측을 완료했고 한도는 소진됐다. 추가 live call은 새 승인 없이 하지 않으며, 기존 실패 실험을 단순 재실행하지 않는다. 과거 한도는 같은 가설의 반복을 막지만, 보존된 실패를 근거로 한 변경된 구현과 새 gate를 영구 금지하지 않는다.
