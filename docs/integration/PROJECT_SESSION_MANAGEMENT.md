# Cue 프로젝트·사용자 세션 관리 (batch101)

## 사용자 경로

- 호스트 폴더 선택기로 기존 프로젝트 폴더를 등록하고 왼쪽에서 선택한다. 프로젝트 추가는 폴더 내 파일을 바꾸거나 모델을 호출하지 않는다. 저장된 목록은 최대 100개이며 중첩 프로젝트·Cue 코드/원장/자격증명 경로는 거부한다.
- 프로젝트 전환은 별도 사용자 확인 후 **현재 Core의 승인 대기/실행/lease/미정리 시도와 비동기 IPC가 없을 때만** 진행한다. 새 요청을 거부하고 ordered `core.close()`가 성공한 다음, 비교·잠금 검사를 거쳐 `cue-config.json`의 활성 root만 원자적으로 바꾸고 앱을 재시작한다. 실패한 close는 설정을 바꾸지 않으며, close 이후 실패는 앱을 fail-closed로 남기고 수동 재시작을 요구한다. 진행 중인 실행을 전환으로 자동 Stop하거나 이어붙이지 않는다. 전환 시 원장은 보존된다.
- 앱 소유 Cue 세션을 만들고 목표 실행을 세션에 연결한다. 한 세션에는 여러 개의 새 Cue run을 담을 수 있다. 과거 실행을 읽고, 보관된 세션을 탐색하며, 기존 세션에서 새 목표를 시작할 수 있다. **이어가기란 과거 모델 대화를 재연결하는 것이 아니라 별도의 goal 준비→봉투 확인→사용자 승인→실행**이다. 새 창/재시작 시 기존 승인 권한은 복구되지 않는다.
- 기존 `cue:workspace-sessions`의 run 단위 기록은 그대로 남아 레거시/연결되지 않은 실행을 읽을 수 있다. 세션 연결은 같은 worktree/승인 대기 run만 허용하고 SQLite 트리거가 교차 프로젝트 연결과 연결 변경/삭제를 막는다. 아카이브는 실행과 원장 내용을 삭제하지 않는다.
- 세션 검색은 현재 프로젝트의 제목과 연결된 실행 목표 앞 4096자에서 최대 100자 리터럴 문자열을 찾는다. 현재/보관 필터와 20개씩 페이지를 유지한다. 검색 결과는 저장 기록이며 현재 실행 가능 여부나 모델 대화 복구를 의미하지 않는다.
- 세션 상세에서 이름을 변경할 수 있다(2026-09-24 후속). 현재 프로젝트의 보관 전 세션만 대상이며 이전 제목 일치 조건으로 경합을 거부한다. 제목은 공백·제어/방향문자·손상된 UTF-8·기본 자동 이름을 거부한다. 변경은 표시/검색 메타데이터만 바꾸고 실행 링크·승인·봉투·모델 대화는 바꾸지 않는다.

## 권한과 미완료

`cue:projects`와 `cue:user-sessions` IPC는 입력·출력을 제한된 DTO로 투영한다. 렌더러는 추가할 경로를 제출할 수 없고, 프로젝트/세션 기록은 provider session handle, 실행/재개/승인 권한이 아니다. 세션 연결 실패는 준비 응답을 돌려주지 않지만, Core가 이미 기록한 미연결 준비 run은 원장에 남을 수 있다. 과거의 `running` 등은 저장 당시 상태이지 현재 OS/원격 종료·청구의 증거가 아니다.

임시 실제 Electron에서 합성 폴더 선택/확인에 의한 프로젝트 전환과 합성 held lease의 거부는 확인했다. 이는 실제 사용자 확인·OS 재시작·활성 공급자 정리 실패 또는 보조공학 인수가 아니다. 프로젝트 이름 변경/삭제와 공급자 대화 재접속은 제공하지 않는다. 대화 맥락을 자동으로 다음 모델에 투입하지 않으며, 일반 코딩 능력과 공급자 자격을 인증하지 않는다. 원본 통합 체크리스트 33/44, 11 미완료 및 live-call budget 제한은 그대로다.
