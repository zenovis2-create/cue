## Done and review contract

The smallest usable result is an explicitly configured local JSON formatting workflow: prepare immutable input and limits, approve, run the qualified local producer, run the independent fixed checker, retain actual output and cleanup evidence, and report acceptance separately from resource accounting. Ordinary startup performs no model request or qualification run. Missing settings, evidence, or accounting support produces a queryable unavailable state and no legacy fallback.

Each unit below has at most two diagnosed correction hypotheses. Run its named focused tests and typecheck/build after a correction; preserve measured regressions rather than weakening assertions. Makers and reviewers remain separate. The author of this plan must not independently approve their own subsequent implementation. No product source was changed while writing this plan; this documentation gate is exact API/path inspection and a parent review, not a repeated runtime test.

## Existing contracts to reuse

- `app/main.mjs:102` currently calls `createCueCore(config)` without an orchestration factory.
- `app/core.mjs` calls a synchronous `runtime.orchestrationFactory({db,config,worktree})` with the actual owned ledger. It accepts an actual host or exact `{available:false,reasons}`. Unavailable keeps the core open and rejects preparation before writes.
- `app/generated-json-host.mjs` returns `{available:true,host}` or unavailable. The bootstrap must unwrap `.host`; passing the outer success wrapper is incorrect.
- `daemon/src/capability-store.ts`: `createCapabilityEvidenceStore(db, now)`, `referencesFor(subjectDigest)`, and `resolveEvidence(ref)`. Admission reads host-owned bytes, checks current subject and age, and rejects fixture evidence.
- `daemon/src/selection/policy-store.ts`: immutable `saveSelectionPolicy`, `readSelectionPolicy`, `readLatestSelectionPolicy`; approval binds a specific revision and digest. User mode preference already persists separately.
- `daemon/src/model-measurement-subject.ts`: fixed installation footprint, isolated Node, actual `process.execPath`, actual SQLite native module, PowerShell and OS identity. `model-control-bundle.ts` supplies pinned client/control identities.
- Generated host already composes stage binding, production capture, durable outer cleanup, native checker and acceptance. Its default executors are real; never persist or configure `executorFactories`, resolver callbacks, arbitrary commands, URLs or evidence bytes through renderer settings.

## Unit 2: honest local invocation accounting before enabling this host

Current `GeneratedJsonHostOptions.accounting`, `SelectionPolicy`, `CompletionEstimate`, `budget.ts`, and migration008 encode money (`currency`, `minor`/`micro`). An arbitrary currency named LOCAL or a fabricated zero USD estimate is not an acceptable invocation budget.

Add an explicit versioned discriminated contract for `local-invocation` alongside the existing monetary contract. Keep legacy serialized policies, digests, run bindings and money ledgers unchanged. New persisted budget/settings rows must distinguish a count from money, using a dedicated count table or a reviewed additive schema; do not reinterpret old amounts. Concrete affected boundaries: `daemon/src/selection/policy.ts`, `policy-store.ts`, `daemon/src/budget.ts`, `daemon/src/orchestration/engine.ts`, `app/orchestration-driver.mjs`/`.d.mts`, `app/generated-json-host.mjs`/`.d.mts`, and approval/observation/report projections. Inspect current migration head before choosing a new migration number.

The local lane admits exactly the qualified producer and checker in their distinct stages. It has no invented quality score, expected latency or monetary estimate. Preserve the four mode preferences and their exact policy bindings, but show that all currently use the same supported pair; do not claim measured efficiency differences. Multiple alternative candidates remain unavailable for automatic ranking until appropriate observations exist. This is an explicit fixed-pair policy, not silently treating unknown estimates as valid in the existing monetary selector.

Define the count in plain language: one reserved stage dispatch attempt, including an attempted launch that fails. Reserve the maximum count atomically with the existing claim and preparation transaction; replay consumes no additional count, retries reserve another count, and no unproved refund occurs. Producer and checker are both visible in the approved total. Host-owned dispatch records prove consumed dispatch counts; they do not prove provider tokens, electricity cost or provider termination. Unknown cleanup still retains ownership and prevents successor execution even when a dispatch count is known. Monetary/provider billing remains unknown or not measured; never display a count as final monetary cost.

Keep max attempts, absolute duration, output bytes/tokens and cancellation bounded. The user explicitly selects this accounting kind and a count limit in setup/approval. Known count use may settle only its own ledger dimension; it must not forge the existing monetary receipt contract. Update execution reconciliation deliberately rather than supplying fake billing receipts merely to unblock the checker.

Gates: new local accounting tests plus existing budget, policy, engine, retry, driver and report tests. Verify monetary byte/digest compatibility, count/money mismatch denial, reserve+claim rollback, exact replay, retry exhaustion, failed dispatch accounting, uncertain cleanup quarantine, both stages covered, and no fabricated score/currency. Run build and an independent review before host activation.

## Unit 3: explicit qualification action and restart discipline

Add a protected qualification entry point (for example `app/qualify-generated-json.mjs`) dispatched by an explicit launcher argument before normal window/core startup. It must run in a fresh Electron process with the same supported main-process runtime mode, package layout and Electron-compatible SQLite module as the normal app. Plain Node or Electron-as-Node evidence is not interchangeable without proving the complete host runtime identity. The isolated worker continues to use its separately pinned Node executable.

Use one `AppDaemon(config)` for ledger/worktree ownership, its actual `.db`, the default compiled collector and no fixture seam. Measure both producer and checker. The explicit operation explains the bounded local model canary and diagnostics; normal app launch never triggers it, including stale/missing evidence. Concurrent app ownership must reject the operation. Await collector and owned cleanup, close through the existing lifecycle, then exit. On failure/unknown preserve evidence and do not publish a replacement PASS. A subsequent fresh normal launch reads the persisted references; do not return user-supplied references through a new permission-bearing IPC.

Current collector checks its own load-time file hash but not every imported dependency's loaded identity. Therefore publish only from a fresh process started after a completed build/source freeze; no hot reload or rebuilding underneath that process. The production bootstrap must also deny installation drift from its process-start identity, not simply rescan changed files and use cached imported code. A protected immutable installation generation, or an entry-point manifest captured before dynamic imports and compared before issuance/dispatch, is needed for this promise. Do not claim a timestamp or just the collector self-hash proves the whole loaded closure. Changes to scripts/policies/probes/host assembly alter subjects and require fresh qualification.

Gates: entry point tests show explicit-only invocation, default native factories, same DB and proper close, no window/legacy launch, no duplicate collection, restart requirement, compiled-path failure, host ABI/runtime mismatch and loaded-footprint drift rejection. Native fixture gates first; then one separately approved source-frozen real measurement under the actual Electron entry point. Persist current subject, raw evidence and cleanup; source changes invalidate that measurement rather than relabeling it.
