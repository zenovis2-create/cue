# Phase 8 — 화면 (P8-1 ~ P8-8) · 실제 UI

Phase 7까지 데몬·봉투·강제·감시·대화·보고가 섰다(테스트 136 통과 / 5 스킵).
Phase 8은 **사람이 실제로 보는 화면**을 만든다. 데이터 계약만이 아니라 **진짜 DOM**이다.

여기서 가장 위험한 실패는 **화면이 원장과 다른 말을 하는 것**이다.
카드에 적힌 숫자가 원장과 1이라도 다르면, 사용자는 없는 일을 믿게 된다. 화면은 예쁠 필요가 없고 **정확해야** 한다.

## 판정 규칙

- `PASS` — 검사가 실제로 통과.
- `PARTIAL` — 일부만. **PASS 아님.**
- `FAIL` / `SKIPPED`(이유 필수).

**기존 테스트(p1~p7)를 수정하거나 삭제하지 마라.** 단정 약화는 그 자체로 FAIL이다.

---

## 기술 제약 (반드시 지켜라)

- **프레임워크 금지.** React/Vue/Svelte 도입하지 마라. **표준 DOM API + TypeScript**로 만들어라.
- 테스트는 **`jsdom` 또는 `happy-dom`** 위에서 **실제 DOM 노드를 조회**해 검증하라. 문자열 스냅샷 비교로 때우지 마라 — `querySelector`, `textContent`, `click()`을 써라. 필요한 devDependency는 설치해도 된다.
- 화면 코드는 **원장에서 읽기만** 한다. UI 모듈에서 `child_process`, `process-launch`, 워커 기동, 봉투 수정 경로에 도달할 수 없어야 한다(P6 프론트도어 규칙과 동일).
- **더미 데이터 금지.** 카드에 표시되는 모든 숫자는 실제 `Ledger` 조회 결과여야 한다. 하드코딩된 상수나 프롭으로 주입된 가짜 숫자가 보이면 FAIL이다.

## P8-1 평소 화면 = 밝은 대화 + 현재 작업 2열

검사: 기본 렌더에 좌우 두 영역이 존재하고, 각각 대화 / 현재 작업을 담는다. DOM에서 두 컨테이너를 조회해 확인.

## P8-2 캡처를 열면 왼쪽만 주석 캔버스, 오른쪽 레일 유지

검사: 캡처 열기 후 왼쪽 컨테이너가 캔버스로 바뀌고, **오른쪽 레일 노드는 같은 노드로 남아 있다**(재생성 아님 — 노드 동일성 확인).

## P8-3 캔버스 전환 후에도 진행 상태·단계 어휘·`중단` 유지

검사: 전환 상태에서 `중단` 버튼이 **DOM에 있고**, `click()` 했을 때 중단 핸들러가 실제로 호출된다.
검사: 진행 상태 텍스트와 단계 어휘가 전환 전후 동일한 값을 보인다.

## P8-4 상태 4종 `유휴 / 작업 중 / 막힘 / 완료`

검사: 네 상태 각각 1개 테스트. 정확한 한국어 리터럴을 단정하라.
검사: 원장 상태값 → 화면 문자열 매핑이 **전수**다. 매핑에 없는 상태가 오면 조용히 `유휴`로 떨어지지 말고 **드러나게 실패**하라.

## P8-5 `최근 작업`은 `task_id` 기준 검색

검사: 세션 목록이 아니라 `task_id`로 조회한다. 세션 id로 검색하는 경로가 없다.

## P8-6 고아 배지는 고아가 있을 때만

검사: 고아 0건이면 배지 노드가 **존재하지 않는다**(숨김 아님 — `querySelector`가 null).
검사: 고아 1건 이상이면 배지가 나타나고 개수가 원장과 일치.

## P8-7 완료·막힘 카드에 `자동 승인 N건 · 거부 M건 · 자세히`

검사: 정확한 문자열 형식을 단정. N·M은 **원장 집계에서 온다**.
검사: `자세히`가 실제로 상세를 연다(`click()` 후 상세 노드 등장).

## P8-8 카드에 `자율성: <수준> · 자동 복구 N회`

검사: 자율성 ③으로 돌린 실행의 자동 복구 횟수가 카드에 보인다.
검사: **원장의 복구 attempt 수와 카드 숫자가 일치한다.** 원장에 attempt를 3건 넣고 카드가 `3회`를 보이는지 확인 — 이 테스트가 Phase 8의 핵심이다.
