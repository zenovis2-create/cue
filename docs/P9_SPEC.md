# Phase 9 — 독립 앱 셸 (Electron) · P9-1 ~ P9-12

Phase 1~8 + 출시 라운드가 끝났다(테스트 165 통과 / 5 스킵, 커밋 `b954463`).
그러나 **Cue는 아직 앱이 아니다.** 실행 창도, 시작 명령도, 첫 실행 설정도 없다.
Phase 9는 지금까지 만든 것에 **Electron 껍데기를 씌워 독립 앱으로 만든다.**

**Buzz는 제품 본체가 아니다.** 선택적 어댑터로 내린다. 앱은 Buzz 없이 혼자 완주해야 한다.

여기서 가장 위험한 실패는 **렌더러가 힘을 갖는 것**이다.
Electron에서 렌더러는 웹 페이지다. 거기에 Node 권한을 주면 Phase 3~5에서 세운 봉투·승인·강제가
**창 하나로 전부 우회된다.** P6에서 프론트도어를 봉인한 것과 같은 규칙을 렌더러에 적용한다.

## 판정 규칙

- `PASS` — 검사가 실제로 통과. `PARTIAL` — 일부만(**PASS 아님**). `FAIL` / `SKIPPED`(이유 필수).
- **기존 테스트(p1~p8, release)를 수정하거나 삭제하지 마라.** 단정 약화는 FAIL이다.
- **외부 상태를 바꾸지 마라** — 실제 게시·릴레이 전송·`@cue` 등록 금지.
- **PARTIAL 3건(P3-16, P4-2, P6-3)을 PASS로 올리지 마라.**

## P9-1 앱 골격과 엔트리포인트

- `app/` 디렉터리를 새로 만든다. 기존 `daemon/`은 **라이브러리로 그대로 쓴다**(재작성 금지).
- `npm start`로 창이 뜬다.
- 검사: `package.json`에 `start` 스크립트가 있고, main 프로세스 진입 파일이 존재한다.

## P9-2 렌더러 봉인 — **이 Phase의 핵심**

`BrowserWindow` 생성 옵션이 반드시 다음이어야 한다:
`contextIsolation: true`, `nodeIntegration: false`, `sandbox: true`.

- 검사: main 소스를 읽어 세 값을 **정확히** 단정하는 테스트(1개).
- 검사: 렌더러 소스에 `require(`, `child_process`, `better-sqlite3`, `fs` 직접 접근이 **0건**.
- 검사: preload가 노출하는 API가 **명시적 허용 목록**이다. 와일드카드로 `ipcRenderer`를 통째로 넘기지 마라.

## P9-3 IPC 채널 허용 목록

- main이 받는 IPC 채널이 `Object.freeze`된 목록으로 고정된다.
- 검사: 목록 밖 채널명으로 호출하면 **거부**된다(테스트 1개).
- 검사: **실행을 시작하는 채널은 승인 레코드 없이는 동작하지 않는다.** P6 프론트도어 규칙과 동일하다.

## P9-4 첫 실행 설정

- 최초 기동 시 원장 DB 경로와 worktree 루트를 정하고 초기화한다.
- 검사: 빈 상태에서 기동하면 설정이 생성되고, 두 번째 기동은 기존 설정을 **재사용**한다(덮어쓰지 않는다).
- 검사: 설정 파일에 **자격증명을 저장하지 않는다**(테스트 1개).

## P9-5 데몬 수명주기

- 앱이 데몬을 소유한다. 창을 닫으면 데몬도 정리된다.
- 검사: 앱 종료 후 고아 프로세스가 남지 않는다.
- 검사: **데몬 크래시 시 자동 재개 금지**(P5 규칙) — 앱은 `blocked/crash`를 보여줄 뿐 되살리지 않는다.

## P9-6 앱 안에서 세 줄 + 봉투 승인

- 자연어 목표 입력 → `무엇을 / 어디까지 / 안 건드릴 것` 3줄 + 봉투 제시 → 사용자 승인.
- 검사: 승인 전에는 실행이 시작되지 않는다.
- 검사: 승인 레코드가 원장에 남고, 그 레코드 없이 진행하는 경로가 0개다.

## P9-7 자율성 선택 ①~③

- 검사: 기본값 ③. 선택이 원장에 기록된다.
- 검사: **자율성이 봉투를 넓히지 못한다**(P5-10 규칙 재확인).

## P9-8 침묵 규율

- 정상 진행 중에는 알림을 띄우지 않는다. **막힘·완료 때만** 보고한다.
- 검사: 정상 진행 구간에서 알림 방출 0건(테스트 1개).

## P9-9 Buzz 없이 완주 — **실기동**

- **실제로 앱을 띄우고**, 실제 태스크 하나를 끝까지 돌려라.
- 목표는 부작용 없는 것으로 골라라(예: worktree 안 파일 1개 생성 후 검증).
- 검사: **Buzz 릴레이에 연결하지 않은 상태**에서 완주한다. `buzz-adapter`가 로드되지 않아도 동작한다.
- 검사: 실제 프로세스 PID를 기록하라. 단위 테스트 대역은 FAIL이다.

## P9-10 완료 카드가 원장에서 온다

- 검사: 카드의 `자동 승인 N건 · 거부 M건`, `자율성: <수준> · 자동 복구 N회`가 **원장 집계와 일치**.
- 검사: 하드코딩·주입 숫자 0건(P8 규칙 재확인).

## P9-11 Buzz는 선택적 어댑터

- 검사: `buzz-adapter` 없이 앱이 기동하고 동작한다(모듈을 제거하거나 비활성화한 상태로 테스트).
- 검사: 앱 코어가 Buzz 심볼을 **정적으로 의존하지 않는다**.

## P9-12 회귀

- 검사: 기존 165 통과 / 5 스킵이 **줄지 않는다.**
