# Phase 10-B — AppContainer 안에서 에이전트가 실제로 일하게 만들기

Phase 10은 **FAIL**이다(커밋 `6cd3271` 기준, 174 통과 / 5 스킵 유지).
배선은 닿았다. AppContainer PID `103284`가 실제로 떴고 원장에 세션/실행 행이 남았다.
그러나 워커가 **일을 시작하기 전에 죽었다**:

> Codex exited 1 — canonicalizing the isolated `CODEX_HOME` returned **Windows error 5 (Access denied)**.

즉 **봉투가 너무 좁아 에이전트가 자기 홈을 못 읽었다.**
Phase 10-B는 **이 한 가지 문제만** 푼다. 재설계가 아니다.

여기서 가장 위험한 실패는 **권한을 넓혀서 문제를 없애는 것**이다.
`CODEX_HOME`을 열어주려다 worktree 격리가 헐거워지면, P3C에서 세운 파일시스템 강제와
R-3에서 junction으로 확인한 차단이 **동시에 무너진다.** 에이전트가 뜨는 것보다 봉투가 새지 않는 게 중요하다.

## 판정 규칙

- `PASS` — 검사가 실제로 통과. `PARTIAL` — 일부만(**PASS 아님**). `FAIL` / `SKIPPED`(이유 필수).
- **기존 테스트(p1~p10, release)를 수정하거나 삭제하지 마라.** 단정 약화는 FAIL이다.
- **PARTIAL 3건(P3-16, P4-2, P6-3)을 PASS로 올리지 마라.**
- **외부 상태를 바꾸지 마라.** 작업은 임시 worktree 안에서만.

---

## 설계 방향 (이대로 하라)

**"일할 공간"과 "작업 대상"을 분리한다.**

- 에이전트 전용 홈(`CODEX_HOME`)은 **worktree와 별개의 격리 디렉터리**로 둔다.
- 그 홈 경로에만 AppContainer SID의 ACE를 부여한다. **홈은 쓰기 가능, worktree는 쓰기 가능, 그 밖은 전부 불가.**
- 홈을 사용자 프로필(`%USERPROFILE%\.codex`)로 가리키지 마라. 그건 봉투 밖이다.
- 실행마다 새 홈을 쓸지 재사용할지는 네가 정하되, **자격증명이 홈에 남지 않아야 한다.**

## B-1 홈 접근 해결

- 검사: AppContainer 워커가 `CODEX_HOME`을 정규화·읽기·쓰기할 수 있다.
- 검사: 그 홈이 **worktree 밖의 별도 격리 경로**이고, 사용자 프로필이 아니다.
- 검사: exit 1 / error 5가 재현되지 않는다.

## B-2 **봉투가 여전히 샌 곳이 없다** — 이 라운드의 핵심

- 검사: **R-3 junction 실험을 다시 돌려라.** worktree 안에서 밖을 가리키는 junction을 통한 쓰기가 **여전히 차단**된다.
- 검사: 홈도 worktree도 아닌 제3의 경로에 쓰기 시도 → **차단**.
- **하나라도 통과하면 B 전체가 FAIL이다.** 에이전트를 띄우려고 격리를 판 것이 되기 때문이다.

## B-3 목표 A 실기동 완주

- 실제 목표 하나를 앱에서 끝까지 돌려라.
- 검사: 실제 PID, 원장 세션 행, **에이전트가 만든 산출물**이 존재한다.
- 검사: 상태가 `completed`다(`blocked/human_required`가 아니다).

## B-4 목표 B 실기동 + 상이성

- 검사: 다른 목표 B를 돌려 **산출물이 A와 다르다**(파일명·내용).
- 검사: 두 실행의 `allowed_actions`가 다르고, PID가 서로 다른 실제 프로세스다.

## B-5 중단이 실제 워커를 죽인다

- 검사: 실행 중 중단 → 그 PID가 **사라진다**. 원장은 중단으로 남는다.

## B-6 자율성 ③/① 복구 대조

- 검사: 실패하는 작업을 ③으로 → 자동 복구 시도 발생, 상한 후 사람에게.
- 검사: 같은 작업을 ①로 → 복구 시도 **0회**.

## B-7 자격증명 미주입

- 검사: 워커 환경·홈·로그·원장 어디에도 자격증명이 없다.

## B-8 회귀

- 검사: 기존 **174 통과 / 5 스킵이 줄지 않는다.**
