# R-06 — 런타임 입력 스키마 검증 사전 조사

조사일: 2026-09-11 · 단계: S0 사전 조사 → S1 최소 계약/S2 disposition · 결정: **direct native guards for current bounded contracts; Ajv/Zod deferred until scale**.

## 계약

입력은 unknown JSON, 출력은 버전형 Cue 값 또는 필드 경로/오류 코드다. TypeScript 단언을 검증으로 취급하지 않는다. 객체/배열 구별, 모든 optional 필드 타입, 알 수 없는 키, 필수 필드, 크기/깊이 상한, 유한한 안전 정수, canonical ID, enum, prototype 키를 검사한다. 문자열 숫자 변환·unknown 키 삭제·기본값 삽입으로 잘못된 입력을 조용히 통과시키지 않는다. 자격은 레지스트리 값만으로 부여하지 않는다.

최소 공유 계약은 ToolCapability/ModelBinding, RunContext, RuntimeEvent, UsageObservation의 버전·identity·순번·명시적 unknown과 지원 불가 값이다. provider 객체를 공통 타입으로 노출하지 않는다. validator는 상태 전이/권한/실제 종료를 판단하지 않는다.

취소/프로세스/재시작: 해당 없음. 제한된 크기의 동기 순수 입력 검사이고 네트워크/자식 실행/저장이 없기 때문이다. 결정성·입력 불변·오류 거부와 시간/크기 제한을 검사한다. remote schema fetch는 허용하지 않는다.

## 후보 비교

| 후보 | 고정 identity·의존/동작 | 사전 판단 |
|---|---|---|
| Ajv 8.17.1 | MIT, direct dependency 4개. compile/validate 및 strict/data modification 옵션 | 다수 JSON Schema 교환이 필요할 때 실험. strict만으로 additionalProperties 거부를 대신할 수 없음 |
| Zod 4.1.5 | MIT, package manifest runtime dependencies 없음. strictObject 제공 | S2 TS 계약이 커질 때 우선 비교. 기본 object 동작에 기대지 말고 strict 설정 명시 |
| Cue native guards | 현재 외부 schema dependency 없음 | S1 소수 계약의 최소 가드 대안. 공통 오류 계약과 누락 없는 음성 fixture가 조건 |

[Ajv manifest](https://github.com/ajv-validator/ajv/blob/v8.17.1/package.json), [Ajv options source](https://github.com/ajv-validator/ajv/blob/v8.17.1/lib/core.ts), [Zod manifest](https://github.com/colinhacks/zod/blob/v4.1.5/packages/zod/package.json), [Zod schema source](https://github.com/colinhacks/zod/blob/v4.1.5/packages/zod/src/v4/classic/schemas.ts).

Ajv는 `removeAdditional`, `useDefaults`, `coerceTypes`를 끄고 `additionalProperties:false`를 명시하는 실험을 한다. 등록된 로컬 스키마만 사용한다. Zod는 strictObject로 검사한다. 소스 패키지의 build/test 스크립트와 실제 npm 설치 lifecycle은 구분한다. package pin은 조사 표본이며 최신/취약점 없음의 주장이 아니다. 편입 전 npm artifact integrity, transitive license/고지, 정확 lockfile, Windows/현재 Node/Electron 호환, CSP/code generation, upstream tests와 유지보수 상태를 추가 확인해야 한다. 이번에는 설치나 네트워크 schema 실행을 하지 않았다.

## 비용 가정

초기 계약 4종·동일 음성 fixture 기준 인일 추정이다. 외부: 조사 0.5 + schema/wrapper 1~2 + 검증 1 + 업데이트당 0.25~0.5. native: 설계/구현 1~2 + 검증 1~2 + 계약 추가당 수동 검증 유지 0.25~0.5. 소수 계약에서는 native가 단순할 수 있으나 계약 수 증가 시 오류 누락 비용이 커진다. 측정 전 효율 우위를 확정하지 않는다.

## 선택한 실험과 게이트

- S1은 dependency 없는 엄격한 최소 계약으로 시작할 후보를 제안한다. S2 disposable harness에서 native와 Zod 4.1.5를 동일 입력으로 먼저 비교한다. JSON Schema 배포 요구가 확정되면 Ajv를 같은 fixture에 추가한다.
- 정상 값 결정성/입력 불변, optional 타입 위반·unknown 키·배열 객체·NaN/Infinity/음수·버전 불일치·과대 입력·prototype 키 거부율 100%, 오류에 secret 원문 출력 0.
- 왕복 직렬화/버전 거부/동일 필드 오류 경로를 검사한다. 권한 획득/실제 취소/P13은 별도 통합 게이트다.
- `evidence/integrations/S2/<run-id>/reuse/R-06/`에 fixture/hash·명령·exit code·시간·artifact 지문을 기록할 계획. **아직 미실행**.
- 최초 실험 1회, 새로운 가설 수정 최대 2회. validator seam 뒤에 숨겨 라이브러리 교체가 domain 계약을 바꾸지 않게 한다. 외부 dependency 변경은 별도 회귀 검증한다.

### 제한된 native 검증 증거

[R-04 실험](R-04.md#실행한-최소-대안-실험)의 strict object/type/unknown-field/accessor/prototype/size 검사와 결정적 JSON 출력은 6 tests PASS다. 명령은 `node --test scripts/reuse/role-contract.test.mjs`, [hash/exit 증거](../../evidence/integrations/S2/20260911-role/reuse/R-04/result.json)를 공유한다. 이 좁은 RoleSpec 경계에서 native 방식의 **limited 실험 통과**만 인정한다. Ajv/Zod 대비 실행 비교, 네 공유 런타임 계약 전체, 제품 경계 검증은 아직 미완료이며 패키지 최종 선택을 확정하지 않는다.

### S2 최종 disposition — 2026-09-12

현재 검증된 제한 계약에는 **strict Cue native guards를 직접 사용**한다. R-04 RoleSpec과 R-05 usage fixture에서 검증한 plain-object, exact-key, prototype/accessor, 타입·수치·크기 경계만 이 disposition의 대상이다. 이 결정은 모든 runtime DTO가 검증되었다는 선언이 아니며, 테스트되지 않은 DTO에 이 결과를 일반화하지 않는다.

Ajv와 Zod 도입은 schema 수, 교환 형식, 공통 오류 계약 또는 유지 비용이 native guard를 넘어서는 시점까지 defer한다. 패키지를 채택·설치하지 않았고 두 패키지와의 runtime 우위도 주장하지 않는다. 새 경계는 자체 음성 fixture와 authority 검토를 통과해야 하며, validator 결과 자체는 정책·자격·실행·정산 권한을 부여하지 않는다. 공유 증거와 한계는 [구현 기록](../../evidence/integrations/S2/20260912-reuse-disposition/implementation.md)에 둔다.
