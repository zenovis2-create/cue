# R-05 — 사용량 정규화 사전 조사

조사일: 2026-09-11 · 단계: S0 사전 조사 → S2 disposition · 결정: **direct native implementation, isolated component accepted; production connection deferred**.

## 계약

입력은 provider/account/model/run/step/attempt, source event ID·sequence, 관측 시각, 누적/증분 구분, provider 원본 사용량이다. 출력은 schemaVersion을 가진 Cue UsageObservation: input/output/cache 세부 토큰, actual/estimated/unknown, 출처·시각·raw digest다. 비용은 별도의 가격 revision·통화·조회 시각이 있을 때만 계산한다. nullable/누락 값은 unknown이며 0으로 바꾸지 않는다. 음수·NaN·무한대·비정수·안전 정수 초과·잘못된 타입을 거부한다. token 종류 포함 관계는 provider별로 선언해 cache 중복 합산을 막는다.

순수 정규화의 취소/프로세스/재시작은 해당 없음: I/O나 상태 저장이 없기 때문이다. 실행 취소와 청구 종료, 영속 중복 제거·예약/정산은 S1 런타임 및 S2 원장 계약에서 별도 검사한다. 정규화 성공이 예약 해제를 허용하지 않는다.

Git 설치/prepare 실행은 하지 않는다. SDK 전체는 네트워크 API 클라이언트이며 순수 정규화 실험에서 호출하지 않는다. 다른 provider SDK는 R-01에서 확인한 고정 버전과 연결하되 아직 공통 사용량 의미가 같다고 가정하지 않는다.

Windows/현재 Node/Electron 호환 실측, npm 배포물 무결성·전체 의존성 고지·SDK upstream tests·유지보수 응답은 미검증이다. 사전 조사는 특정 revision의 타입/manifest 확인이며 최신 안정성 보증이 아니다. SDK import 없이 provider fixture를 받을 수 있어 이번 기능만으로 SDK 전체를 설치할 이유는 없다.

## 비용 가정

동일 두 provider fixture와 정규화 범위의 인일 추정이다. SDK 기반: 조사 0.5 + Cue 변환 1~2 + 검증 1~2 + 업데이트당 0.25~0.5. 독자 프로토콜/타입부터 개발: 설계/구현 2~3 + 검증 1~2 + provider 변경당 0.5~1. 기존 SDK가 R-01에서 채택되면 타입 재사용은 유리하지만 Cue 예산 엔진 구현 비용은 어느 대안에도 남는다. 실제 측정값·절감율 없음.

## 선택한 실험과 게이트

- Cue 소유 순수 normalizer에 고정 provider fixture를 입력한다. source event ID/누적 여부/unknown 정보가 유지되어야 한다.
- cache 포함 관계, 누적 10→15와 중복 15, 역순 이벤트, 부분 스트림, 누락/null, 잘못된 숫자, 서로 다른 account/currency를 검사한다. 단일 이벤트 변환과 상태 합산 fixture를 분리한다.
- S2 상태 계층에서 중복 비용 0, 병렬 예약 초과 0, 취소만으로 불확실 비용 예약 해제 0을 추가 검사한다. pure normalizer 통과로 이 게이트를 완료 표시하지 않는다.
- `evidence/integrations/S2/<run-id>/reuse/R-05/`에 fixture/hash·명령·exit code·시간을 기록할 계획. **미실행: 증거 값 없음**.
- 최초 1회/새 가설 수정 최대 2회. provider 누적 의미 미확인은 unknown으로 유지하고 엄격 예산 후보에서 제외한다. provider mapping seam을 두어 SDK 변경이 원장 계약으로 전파되지 않게 한다.

### 실행한 최소 대안 실험

상위 작업에서 [usage-normalization.mjs](../../scripts/reuse/usage-normalization.mjs)와 [테스트](../../scripts/reuse/usage-normalization.test.mjs)로 native 순수 정규화 실험을 수행했다. 실제 fixture는 OpenAI Chat/Ollama 필드이며 위 Anthropic SDK 런타임이나 cache 의미를 검증한 것은 아니다. 이번 출력은 provider/status/input/output/cachedInput/total/totalSource에 한정하고 run/account/sequence/가격/중복 정산은 아직 포함하지 않는다.

필드 대조 출처: OpenAI SDK commit `3c4e4d26e3aebd422bc73787e4fcbd1773607785`의 [Chat usage 참조](https://github.com/openai/openai-node/blob/3c4e4d26e3aebd422bc73787e4fcbd1773607785/src/resources/chat/completions/completions.ts)와 [CompletionUsage 정의](https://github.com/openai/openai-node/blob/3c4e4d26e3aebd422bc73787e4fcbd1773607785/src/resources/completions.ts), [OpenAI Docs](https://developers.openai.com/api/reference/ruby/resources/chat/subresources/completions/methods/retrieve), [Ollama generate 공식 문서](https://docs.ollama.com/api/generate) (2026-09-11 조회). OpenAI total은 prompt+completion이며 cached는 prompt 상세다. Ollama prompt_eval_count/eval_count는 입력/출력 카운터로 매핑했다. 현재 Ollama 문서의 prompt_eval_cached_count는 이번 최소 실험에서 지원하지 않고 null로 유지한다. 문서/API 버전과 실제 연결값 대조는 후속 gate다.

`node --test scripts/reuse/usage-normalization.test.mjs` exit 0, 8 tests PASS. unknown을 0으로 바꾸지 않음, partial 유지, cache를 input 부분집합으로 처리, 음수/overflow/불일치 거부, 결정성/메타데이터 미노출을 검사했다. [result.json](../../evidence/integrations/S2/20260911-usage/reuse/R-05/result.json)의 sourceHash는 `2D5EB58C2D1D85A9BDEAF5B00840A780FAAAAEFD1585D9C5BCE4668517F375FC`이며 명령·exit code·testHash·시각을 함께 기록한다. [실행 로그](../../evidence/integrations/S2/20260911-usage/reuse/R-05/test.log)와 원본 hash가 일치하는 revision만 이 결과를 인용한다.

판정: 이 제한된 native fixture는 **limited 실험 통과 / 독립 검토 대기**. 실제 provider 호출·SDK 편입·가격 정확성·예산 예약/정산·제품 사용량 통합은 미완료다. 원본 observation provenance 및 누적/증분 의미를 연결하는 후속 실험은 유지한다.

### S2 최종 disposition — 2026-09-12

`scripts/reuse/usage-normalization.mjs`의 **Cue direct native isolated component를 OpenAI Chat/Ollama fixture 계약에 한해 채택**한다. 제품 실행 경로 연결은 defer한다. 기존 독립 검토의 26/26 결과와 이번 재실행 8/8은 absent/partial/unknown 보존, cache 중복 방지, malformed counter 거부, 임의 provider metadata 비보존만 뒷받침한다.

이 component의 출력은 관측 후보다. 가격을 정하거나 candidate eligibility를 부여할 수 없고, reservation size, settlement finality 또는 provider stop/과금 종료 truth를 정할 수도 없다. 현재 Cue policy, host admission, budget reservation/receipt verifier와의 별도 연결 전에는 선택·예산·launch 입력으로 승격하지 않는다. SDK adoption, provider compatibility, 실제 usage event, 비용 계산을 완료했다고 주장하지 않는다.

재검증한 SHA-256은 source `2d5eb58c2d1d85a9bdeaf5b00840a780faaaaefd1585d9c5bce4668517f375fc`, test `0baaf73f2b173ef517cb64bc6064813b2266b955a61971505ee4f8ebf4a872a2`, 기존 result artifact `499bdfb657332ff97b110a9796786f16aa6f28f88e0e36f73f17af98ffc696ad`이다. 최종 reconciliation과 남은 연결 한계는 [구현 기록](../../evidence/integrations/S2/20260912-reuse-disposition/implementation.md)에 둔다.
