# R-01 — 모델 API·스트리밍 transport 사전 심사

조사일: 2026-09-11 · 단계: S0 → S1 · 상태: **defer (실험 대상 선정, 채택 아님)**

## 완료 기준과 범위

이 기록의 완료는 고정 소스·계약·후보 비교·직접 구현 비용·실험 계획의 존재와 독립 검토다. 조사 1회, 실험 1회 후 새 가설 수정 최대 2회. 현재는 공개 소스/문서만 읽었으며 설치·유료 요청·사용자 홈 변경·실험 실행은 없다. fixture hash, 실행 시간/자원, exit code는 아직 미측정이다.

## Cue 계약

`ModelRequest(run/step/attempt, canonicalModel, endpointRef, authRef, input, limit, AbortSignal) → AsyncIterable<ModelEvent>`를 교체 경계로 둔다. 출력은 delta, usage, terminal, error를 구분한다. transport는 파일 쓰기·도구 호출 실행·후속 모델 선택·자동 재시도를 하지 않는다. provider 객체를 원장 타입에 직접 넣지 않는다.

`host-codex-runtime.ts`는 이미 컨트롤러와 AppContainer 워커의 소유·정리를 관리한다. 모델 API 경로는 이 쓰기 실행 권한을 상속하지 않는다. `adapters/registry.ts`의 등록도 자격 부여가 아니다. endpoint/auth/model 정책 검증을 거친 호스트 경로만 요청을 수행하며 renderer에 인증값을 전달하지 않는다.

취소는 client transport 닫힘과 provider 실제 종료를 별도 관측한다. AbortSignal 성공만으로 원격 계산/과금 종료를 확정하지 않는다. EOF/HTTP 200을 완료로 해석하지 않고 프로토콜의 성공 terminal을 요구한다. 사용량 누락은 unknown이며 0이 아니다. 모르는 이벤트는 제한된 진단으로 남기되 성공 증거로 사용하지 않는다. JSON 크기·스트림 버퍼·전체 요청 기한을 제한한다. 재시작 후 미완료 요청은 대조 전 재송신하지 않는다.

SDK의 기본 retry는 Cue 예산 밖 추가 요청을 만들 수 있다. 고정 문서는 일반 retry를 `maxRetries: 0`으로 끄더라도 workload identity의 특정 401 재인증 요청이 남을 수 있다고 설명한다. 초기 SDK 실험은 주입된 가짜 인증만 사용하고 실제 요청 횟수를 fixture 서버에서 계수한다. SDK가 제공하는 도구 실행 helper/agent loop는 사용하지 않는다. [SDK 설정](https://github.com/openai/openai-node/blob/3c4e4d26e3aebd422bc73787e4fcbd1773607785/docs/configuration.md)

- SDK: [manifest](https://github.com/openai/openai-node/blob/3c4e4d26e3aebd422bc73787e4fcbd1773607785/package.json), [Apache-2.0 원문](https://github.com/openai/openai-node/blob/3c4e4d26e3aebd422bc73787e4fcbd1773607785/LICENSE). 배포 시 LICENSE와 적용 가능한 NOTICE/수정 고지를 확인한다. optional peer 포함 실제 tarball 의존성은 미심사다.
- parser: [manifest](https://github.com/rexxars/eventsource-parser/blob/6519a0f70dfeb22f829e5c696da2cb4988d64c6a/package.json), [API·버퍼 제한](https://github.com/rexxars/eventsource-parser/blob/6519a0f70dfeb22f829e5c696da2cb4988d64c6a/README.md), [MIT 원문](https://github.com/rexxars/eventsource-parser/blob/6519a0f70dfeb22f829e5c696da2cb4988d64c6a/LICENSE). 저작권/허가 고지 보존. 버퍼 상한은 문자 수이므로 바이트/총출력 상한도 Cue에서 둔다.
- [공식 스트리밍 문서](https://developers.openai.com/api/docs/guides/streaming-responses)는 2026-09-11 조회한 변경 가능한 참고 자료다. 고정 SDK 소스를 대체하는 버전 증거가 아니다.

두 후보 모두 manifest에 테스트 경로가 있으나 upstream 테스트를 실행하지 않았다. 공개 API가 있으므로 workspace 내부 코드 복사보다 버전 고정 package 경계가 유리하다는 사전 판단이다. 유지보수 속도/취약점 부재는 확인하지 않았다. 업데이트는 별도 PR에서 tarball 무결성·license·의존성 변경과 fixture 회귀를 검토한다. 버전별 API와 Cue 정규화기만 교체하고 원장 계약은 보존한다. 필요한 upstream patch는 현재 0개(아직 연결하지 않았기 때문)이며 실험 후 재평가한다.

## 같은 범위의 비용 비교

실측 일정이나 절감률은 없다. SDK 경로는 생성된 provider 타입/오류/stream 처리 유지 부담을 줄이지만 옵션 감사·버전 갱신·이벤트 매핑이 필요하다. parser 경로는 SSE framing 유지 부담만 외부에 맡기고 HTTP/의미 검증을 직접 소유한다. 직접 구현은 의존성 심사가 작지만 UTF-8 분할·CR/LF·다중 data·미완성 이벤트·크기 상한의 표준 회귀를 계속 소유해야 한다. 각 경로의 연결 코드량, 외부 patch 수, 테스트 작성/수정 시간과 실패 수를 같은 fixture에서 기록해 총비용을 비교한다. 현재 근거만으로 adopt를 선언하지 않는다.

## 다음 fixture와 제품 게이트

1. disposable 디렉터리에서 고정 package/tarball hash를 기록하고 install script 없이 비교한다. 정상 delta+terminal+usage, usage 누락을 입력한다.
2. UTF-8 byte 경계·CRLF·다중 data·잘못된 JSON·추가 필드·미완성 EOF·stream 내부 error·버퍼 초과를 검사한다. 요청 횟수는 항상 1이다.
3. 응답 헤더 전/첫 chunk 후 취소, 느린 응답 timeout, 두 병렬 요청 중 하나 취소를 측정한다. 상대 요청 유지와 로컬 socket 종료를 확인한다. provider 종료는 미측정 상태를 유지한다.
4. redirect/비허용 origin·인증 진단 노출을 차단한다. 429/500/401에서 숨은 retry가 없는지 계수한다. 재시작 시 자동 송신 0을 Cue attempt fixture로 검사한다.
5. 입력 hash, 명령, exit code, 실제/fixture 구분을 `evidence/integrations/S1/<run-id>/reuse/R-01/`에 저장한다. 필수 실패 0과 비용 이점·독립 검토 후에만 adopt/limited로 바꾼다. 실제 API 계정·Windows 취소·권한 실측은 별도 제품 지원 게이트다.

## 2026-09-11 실험 추가 기록

사전 심사 후 native fetch 기준선의 loopback HTTP 실험을 수행했다. `scripts/reuse/model-transport.mjs`의 단일 요청 경계와 `scripts/reuse/model-transport.test.mjs`의 18개 검사는 최종 exit 0이다. 최초 실패와 수정 1회, 파일/fixture hash, 환경, 미검증 항목은 [실험 결과](../../evidence/integrations/S1/20260911-transport/reuse/R-01/RESULT.md)에 보존했다. 범위는 chat-completions SSE와 Ollama NDJSON의 제한된 텍스트 경로이며 Responses API가 아니다. 위 사전 심사 시점의 미실행 문구는 조사 단계 기록이다.

외부 SDK/parser 비교 실행은 아직 없으므로 최종 채택은 계속 defer다. 독립 검토자: 상위 작업에서 배정 예정/미검토. S1 지원 완료 및 외부 부품 채택 완료로 체크하지 않는다.
