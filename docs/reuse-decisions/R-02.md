# R-02 — CLI 연결과 정규화 이벤트 사전 조사

조사일: 2026-09-11 · 단계: S0 → S1 · 상태: **사전 선별 및 오프라인 fixture 실험 완료 / 채택·실제 연결 미완료**

범위: Codex 기준선을 보존하면서 두 번째 에이전트의 모델 전용 연결을 준비한다. 저장소 공개 여부를 재배포 권한으로 해석하지 않는다. 설치·인증 복사·유료 호출·외부 코드 편입은 하지 않았다.

## 기능 계약

- 입력: 검증된 실행파일 identity/version/hash, canonical model ID, auth reference, run/step/attempt, immutable envelope/policy hash, timeout, 제한된 프롬프트. 인증 값은 renderer·명령 인자·이벤트에 넣지 않는다.
- 출력: vendor thread/session/turn ID를 Cue attempt에 연결한 순번 있는 이벤트, text delta, usage의 actual/estimated/unknown 구분, transport 종료 및 실패 원인.
- 공급자가 완료를 보고한 것과 Cue 요구사항 검증 완료를 분리한다. 잘못된 JSON, 잘린 스트림, terminal 누락, 초과 프레임, 알 수 없는 실행 요청은 fail closed다.
- cancel-requested → provider-terminal → 실제 로컬 controller/worker 정리 확인을 별개로 기록한다. 원격 과금 종료는 로컬 프로세스 사망으로 증명하지 않는다.
- 재접속/재시작은 상태 대조만 한다. 미완료 쓰기 및 외부 부작용을 자동 재실행하지 않는다. 프로토콜 ID는 idempotency 보장을 의미하지 않는다.
- workspace 도구 실행은 기존 Cue 경계만 사용한다. CLI의 자체 권한 승인을 Cue writer lease/승인으로 대체하지 않는다.

## 현 코드에서 유지할 경계

[host-codex-controller.ts](../../daemon/src/host-codex-controller.ts)는 `HostCodexRpcSession`과 `buildHostThreadStartParams`에서 Codex 전용 wire contract를 소유한다. `cue_workspace`만 제공하며 worker 자식 실행 금지를 설명한다.

[host-codex-runtime.ts](../../daemon/src/host-codex-runtime.ts)의 `RunningHostCodexRun`, `settleHostRuntimeTeardown`, 소유권 등록 및 검증된 트리 종료는 vendor 이벤트 파서와 분리해 유지한다. 공통 어댑터는 이 경계의 stop/done/events를 감싼다. RPC 응답으로 종료를 확정하거나 별도 원장을 만들지 않는다.

[tool-home.ts](../../daemon/src/tool-home.ts)는 Codex 전용 clean home/allowlisted env다. 이를 이름만 바꿔 Claude 인증 홈에 재사용하지 않는다. 사용자 전체 홈이나 환경을 상속하지 않는 원칙만 공유하고 제품별 인증 계약은 별도 확인한다.

## Claude 모델 전용 프로토타입

첫 구현은 실행하지 않는 launch-spec builder와 합성 stream-json fixture 파서로 제한한다. 모델 이름을 코드에 고정하지 않고 검증된 binding을 요구한다.

- print, stream-json, verbose, partial message 포함, no-session-persistence 설정을 대상으로 버전 지원을 확인한다.
- `--tools ""`는 built-in만 제한한다. MCP는 별도 차단하고 빈 명시 구성 + strict MCP 옵션을 검증한다.
- 현재 공식 문서의 `--safe-mode`는 hooks/skills/plugins/MCP 등 customization 제거를 설명한다. `--restricted`는 v2.1.248+에서 제공한다. 설치 바이너리의 도움말/지문으로 지원이 확인되기 전에는 실행하지 않는다. 지원 안 되는 옵션을 빼고 실행하는 fallback은 금지한다.
- clean controller cwd/home, allowlisted env, 인증 참조만 사용하는 전용 launcher가 필요하다. managed settings, credential helper, 자동 업데이트, 시작 시 부작용 여부를 실제로 측정한다.
- native Windows CLI 실행 지원과 native sandbox 미지원은 별개다. tools-off는 OS 격리 증명이 아니다. workspace 접근을 허용하지 않은 입력 텍스트 처리부터 검증하고, 최종 tool bridge는 별도 P13 gate로 남긴다.
- model-only 결과는 제안 텍스트다. 도구 사용 이벤트가 오면 차단하며, 이 경로를 두 번째 쓰기 에이전트의 완성으로 체크하지 않는다.

## 직접 구현 대안과 비용

직접 구현 대안은 새로운 CLI/harness를 만드는 것이 아니라 Cue 소유의 얇은 vendor 프로토콜 어댑터를 작성하는 것이다. Codex는 기존 RPC 코드를 감싸고 Claude는 엄격한 JSONL parser/launch builder부터 만든다. SDK가 필요한 custom tool streaming을 안정적으로 제공하면 같은 계약 안에서 SDK로 교체할 수 있다.

| 경로 | 조사·연결·수정 | 검증·업데이트 | 상대적 예상 노력 |
|---|---|---|---|
| 기존 Codex + 얇은 Claude 어댑터 | 2개 프로토콜 매핑과 공통 이벤트 경계, 외부 patch 0 목표 | 파서·종료·환경 계약 회귀를 Cue가 소유 | 초기 중간 / 지속 중간 |
| 공식 SDK 의존 | 패키지·실행 프로세스 제어 API·auth/terms 검증 필요 | SDK 버전별 lifecycle 변화 검증 | 초기 중간 / 지속 중간; 직접 방식보다 저렴한지 아직 미측정 |
| Paseo adapter 추출 | 내부 launch/env/state 의존 분리, Cue 소유권 재연결 | Paseo와 SDK 두 upstream 및 추출 patch 추적 | 초기 높음 / 지속 높음 추정 |

정량 시간·절감률은 측정하지 않았다. 비용 추정은 위 의존 경계 관찰에 근거한 가설이다. 직접 어댑터 대비 이점이 입증되기 전 외부 adapter 코드를 편입하지 않는다.

## 실험·채택 게이트

이번 조사: GitHub API로 SHA 확인, 고정 source/README/license 및 공식 제품 문서 열람. 부모 작업에서 read-only `--version`으로 Claude 2.1.267, Ollama client 0.32.14(서버 실행되지 않음), Node 24.18.0/npm 12.0.1을 관측했다. 이는 인증·설치 binary hash·실제 모델 접근·실행 자격 증거가 아니다. 신규 CLI install/model run/auth/paid call 없음. 실제 연결 실행시간/자원/프로세스 사망 증거는 **없음**이다.

오프라인 보조 실험: [launch-spec/fixture module](../../scripts/reuse/claude-launch-spec.mjs), [tests](../../scripts/reuse/claude-launch-spec.test.mjs). `node --test scripts/reuse/claude-launch-spec.test.mjs` 결과 **9 passed / 0 failed**, exit 0. 정확히 2.1.267만 허용하고 과거/미검토 미래 버전은 거절한다. argv/env/입력 경계 및 합성 JSONL의 도구 요청·실패/누락/중복 terminal 거절을 검사했다. 모듈은 CLI를 실행하지 않으며 `auth: unconfigured`, `executable: false`를 반환한다. 모델 binding의 `identityVerified`는 caller가 제공한 증거 결과를 전제로 하는 fixture 필드이며 모델 탐지기가 아니다. parser는 일부 이벤트 형식에 대한 오프라인 실험이고 live 전체 schema/stream ordering 검증기가 아니다. 따라서 아래 실제 프로토콜·수명주기 gate를 체크하지 않는다.
